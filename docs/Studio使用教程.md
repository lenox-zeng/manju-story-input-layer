# Manju Studio 使用教程

> Manju Studio 是输入层图形管理台（本地 Web），只读/写**输入层**（`config.json` / `state/story` / `input`），**不碰渲染/成片**。用于可视化配置、跑上游、看改分镜、编辑资产、发布契约。

v2.0 运行目录自带 Studio；端口默认 **8092**，可与 v1.2 的 8091 同时运行。
两套的 `state/`、`input/`、`output/` 不共享，启动时用 `scripts/studio.ps1` 把
`MANJU_ROOT` 固定到 v2.0 目录。

> 命令行教程见 `docs/小说输入层使用教程.md`。两种入口共用同一套后端：
> Studio 的「生成」在后台调用 `python -m manju.story_cli`，「发布契约」复用
> 同一套编译与 gate/drama 审计，最终产物完全一致。

---

## 0. 5 分钟快速开始

1. 按根目录 `README.md` 完成安装；纯净包首次使用先 `Copy-Item config.example.json config.json`。启动 Studio 前设置环境变量 `DEEPSEEK_API_KEY`；也可以只在「系统 → 配置」里临时输入 Key（仅保存在本次 Studio 会话，重启失效）。
2. 启动 Studio：
   ```powershell
   .\scripts\studio.ps1
   ```
   浏览器打开 `http://127.0.0.1:8092`。
3. 进入「生成」，选择 `input/` 下你自己的小说（纯净包不附样书）；分集方式先用默认的
   **按剧情自动分集**，生成范围留空（或填 `1`–`2` 只试跑前两集）。
4. 点 **开始生成**。下方日志会逐阶段显示；成功后页面会给出两个路径：
   `input/<小说名>/`（契约产物）与 `state/story/<小说名>/`（可编辑中间产物）。
5. 进入「分集 · 分镜」逐镜修改；进入「角色 · 场景 · 道具」「画风 · 世界观」调整资产与设定。
6. 修改后页面底部出现发布条，点 **重新编译契约** 写入 `input/`。这是确定性步骤，不调用模型，可反复执行。
7. 想回到命令行继续跑同一部小说时，直接用相同的 `state/story/<小说名>/` 缓存：
   ```powershell
   python -m manju.story_cli input\my_story.txt --resume --yes
   ```

## 1. 启动

在 **v2.0 运行目录**（含 `config.json` 与 `manju/`）下执行：

```powershell
.\scripts\studio.ps1                          # 默认 http://127.0.0.1:8092
# 等价于
python -m manju.studio --port 8092 --host 127.0.0.1
# 自定义端口/地址
.\scripts\studio.ps1 --port 8093 --host 127.0.0.1
```

浏览器打开 `http://127.0.0.1:8092` 即可。`Ctrl+C` 停止。
如果 8092 已被占用，换一个端口；不要直接复用 v1.2 的 8091，否则容易看错数据目录。

界面按工作流从左到右组织：

| 分组 | 视图 | 用途 |
|---|---|---|
| 流程 | **生成** | 选小说、分集方式、本次生成范围、画面参数 |
| 流程 | **分集 · 分镜** | 按集查看/修改镜头 |
| 流程 | **角色 · 场景 · 道具** | 编辑资产文本 |
| 流程 | **画风 · 世界观** | 编辑 `visual_bible` 与 WorldBible |
| 流程 | **人物关系** | 查看关系图谱 |
| 交付 | **发布契约** | 重编译、查看产物路径与发布结果 |
| 系统 | **配置** | 文本模型、改编策略等长期设置 |
| 系统 | **LLM 日志** | 每次模型调用的模型/提示词/输出/耗时/token/估算费用 |

顶栏只保留**当前小说**下拉与状态胶囊（模型、工作层/成品、待发布）。
`保存画风`、`重新编译契约` 不再放在顶栏：它们属于当前编辑/交付步骤，
分别位于「画风 · 世界观」页和「发布契约」页；有未发布修改时，页面底部还会
出现固定的发布条。

> 首次打开前建议先在「生成」页跑一部小说；否则分镜/资产等视图会显示空状态。
> 顶部「当前小说」只决定**查看/编辑哪部小说**，与「生成」页选择要跑哪部小说是两件事。

## 2. 配置（长期设置）

这里只放**长期生效**的设置，保存到 `config.json`：

- **模型服务商（provider）/ base_url / model**：走 **OpenAI 兼容协议**，`provider` 只是标签（下拉含 `deepseek` / `openai`），实际由 `base_url` + `model` + Key 三者决定服务。默认 `https://api.deepseek.com/v1`，模型如 `deepseek-v4-pro`（更强）/ `deepseek-flash`（更快，默认）；也可填任意 OpenAI 兼容端点（如 `https://api.openai.com/v1`、火山方舟、本地 vLLM/Ollama）。
- **API Key**：留空则沿用环境变量或旧配置。**在页面输入的新 Key 只保存在 Studio 进程内存**，随生成子进程下发，不写 `config.json`；界面只显示来源和掩码，不显示完整 Key。Studio 重启后需要重新输入，长期使用请设 `DEEPSEEK_API_KEY`。
- **并行数**：同时生成多少集/场。**温度不在这里配置**：各生成阶段已固定为
  `0.0`（长篇卷摘要 `0.2`），保证契约字段、镜头编号和续跑结果可复现。
- **每集字数（仅回退分集）**：只有关闭情节分集、又没指定集数时才使用。
- **自动分集上限（安全阀）**：防止超长小说一次生成过多集。

> **本次生成跑哪几集、画幅、单集时长不在这里设置**，请到「生成」页按次选择。
> 旧版配置页曾重复出现「集数 / 起–止集 / 画幅 / 时长」，现已合并到生成页，避免两处各改一半。

---

## 3. 画风 · 世界观

保存到 `state/story/<小说名>/outline.json`，改完点 **保存画风与世界观**，
再到「发布契约」重编译：

- **画风 visual_bible**：`style_keywords`（逗号分隔）、`main_colors`（hex，逗号分隔）、`reference_styles`（逗号分隔）、`do_dont`（每行一条；兼容 LLM 偶发返回的 `{DO,DON'T}` 对象，自动展平，禁忌行自动加「忌：」前缀）。
- **镜头语言细节**：`medium` / `film_stock` / `lens` / `lighting` / `palette` / `texture` / `contrast`。
- **世界设定 WorldBible**：`factions`（势力）、`geography`（地理）、`timeline`（时间线）、`rules`（规则），各为对象数组；空数组表示未定义。

> 若这些字段为空，先到「生成」页跑一部小说生成。

## 4. 生成（小说 → 中间产物）

**临时工作层**：生成先写到临时目录 `state/story/.work_<小说名>/`（中间产物）与 `input/.work_<小说名>/external/`（编译产物）；只有**完整成功**才固化到最终目录 `state/story/<小说名>/` 与 `input/<小说名>/`，并在 `state/story/<小说名>/` 写 `_completed.json`、清空临时。失败则临时目录保留，可直接续跑。

### 4.1 分集方式（决定总集数）

三选一：

- **按剧情自动分集（推荐）**：程序先读全文，按情节原子/戏剧单元自动决定集数；每集字数不参与。Studio 会显式传 `--chapters-per-episode 0`，避免被 `config.json` 里旧的章节默认值悄悄切回章节模式。
- **指定总集数**：按指定集数拆分（`--episodes N`）。
- **每 N 章一集**：按小说章节切分（`--chapters-per-episode N`）。

### 4.2 生成范围（可选，起止集）

只跑其中一段，用于续跑或局部重做：**起始集 / 结束集**，留空 = 全部。
它**不改变分集总数**，也不改变集号；范围跳跃（如先 1–4、下次 5–8）会自动继承上一集**剧本末态**（`script_ep{N-1}`）与**分镜终态**（`board_ep{N-1}`），跨集衔接不中断；前提是上一集已完整生成且未清临时（上一集缓存缺失会 WARN 并从空状态开始）。

> 这两个概念互不替代：
> - **分集方式/总集数** = 整部小说改编成几集；
> - **生成范围/起止集** = 这一次实际跑第几集到第几集。

### 4.3 其他

- **画幅 / 单集时长(s)**、**小说选择**都在本页。
- **高级选项 → 先清临时工作层再重跑**：只清当前小说的 `.work_<小说名>`，已发布成品保留；失败重试通常不需要。
- 每次开始生成时，本页参数会写回 `config.json` 的 `studio.generation`，下次自动预填；它只是“上次使用”，不再在配置页重复展示。

生成时下方有实时状态与日志窗口（黑底），可实时看到每个阶段；完成后会给出两个产物路径（编译产物 `input/<小说名>/`、中间/可编辑产物 `state/story/<小说名>/`，含 `board_epNN.json`），路径可整段选中复制；同时提供跳转到分镜或发布页。失败时会显示退出码与原因（常见为质量门未过 / 模型不可用），并提示直接续跑。

**生成默认自动续跑**：每次只跑还没生成/还没通过质量门的阶段，已通过的阶段缓存直接复用（每部小说独立 `.work_<小说名>` 目录）。中途失败、或切换别的书再回来，都能无缝接着补未完成的部分。

### 4.4 LLM 调用日志（排查慢 / 失败）

左侧导航点 **「LLM 日志」**，图形化查看 `state/llm_trace.jsonl`——流水线**每调用一次大模型**就记录一条：

- 阶段（法典 bible / 分集 episodes / 角色 cast / 美术 art / 剧本 script / 分镜 staging…）、**实际模型**、第几次尝试、成败、耗时（秒）、输入/输出/缓存命中 token 数；
- 页头汇总全部记录的模型、输入/输出、缓存命中率，以及按 DeepSeek 官方价估算的费用区间 **空闲–高峰**（CNY）。旧记录没有 `model` 字段时按当前配置模型推断并标 `*`，没有缓存明细时输入按未命中保守估算；未知模型按 Flash 兜底估算并在页头提示；
- 空闲/高峰按 DeepSeek 官方时段区分：北京时间工作日 09:00–12:00、14:00–18:00 为高峰，其余为空闲。费用是本地估算，包含失败重试产生的 token，实际账单以平台为准；
- 失败条目标红并显示错误原因；**点任意一条可展开**查看 System 提示词、User 输入、模型原始 Output（前几百字），便于判断是字段缺失、输出被截断、还是模型把思考写进了 JSON。

**为什么慢 / 卡在哪**：生成耗时几乎全部在**等大模型逐阶段返回**；编译、质量门、读写文件都在秒级。若某阶段输出不合格会自动重问，**失败重试是耗时翻倍的主要原因**——让每阶段一次通过即是最有效的提速。单集内各阶段有前后依赖只能串行；多集的剧本/分镜会按 `config.json` 的 `llm.parallel` 并行。

## 5. 分集 · 分镜

- 分集卡片显示：集号、标题（来自 outline）、场数、镜数、总时长。
- 点某一集进入镜头列表：按场景分组，每个镜头是一个可展开卡片；摘要行显示镜号、景别、时长、coverage、运镜和内容摘要。
- **可编辑**：`shot`（内容摘要）、`prompt_en`、景别（size）、时长（seconds）、运镜（camera）、motion、coverage、cut_reason。改完点该镜的 **保存该镜**。
- 保存只写中间产物 `board_epNN.json`；页面底部出现「有修改尚未发布」发布条，点 **重新编译契约** 才写入 `input/`。
- **旁白 / 场间转场不在镜卡片里编辑**：它们在剧本阶段生成到 `state/story/<小说名>/script_epNN.json` 的 `scene.narration` / `scene.transition_in`，编译时旁白按拍分配到镜头、转场只落在场次首镜，并写入 `input/<小说名>/external/epNN/script.json`。Studio 目前不提供逐条编辑；需要调整时重新生成该集，或修改对应的 `script_epNN.json` 后重新编译（不要改动 `scene_id` 与拍号，否则旁白会失去归属）。

## 6. 角色 · 场景 · 道具

三个标签页，可看可改：

- **角色**：`id`、`name`、`identity_prompt`、`negative_prompt`。
- **场景**：`id`、`name`、`plate_prompt`、`negative_prompt`。
- **道具**：`id`、`name`、`prompt`、`scale`。

每行点 **保存** 写回 `cast.json` / `art.json`，之后需重编译生效。

> 输入层不提供“分镜形象提示模式”。分镜提示词固定只写动作/场景/表演；角色身份通过 `ref_characters`、表情/服装状态与 `story_assets.json` 的 `identity_prompt` / `identity_anchor` 输出，由实现层按自己的参考图、锁脸或纯文本方案决定是否注入。

## 7. 人物关系图谱

SVG 关系图，数据来自 `cast.persona.relationship_spec`（或 `relationships`）：角色节点 + 关系边（连线=类型，鼠标悬停见备注）+ 类型图例。若存在指向圈外角色的关系，下方会列出"未在图中的关系"便于排查。

## 8. 发布契约

入口有两处：

- 左侧 **发布契约** 视图；
- 有未发布修改时，任意页面底部的固定发布条。

发布做三件事：

1. 读取当前小说 `state/story/<小说名>/` 下的 outline / cast / art / script / staging / board；
2. 先跑质量门，编译后再跑 gate/drama 审计；
3. 全部通过才写 `input/<小说名>/` 契约（`external/plan.json`、`external/epNN/{script,director}.json`、`epNN/storyboard.json` 等），并清除脏标记。

这是确定性步骤，**不调用文本模型**，可以反复执行。硬门或审计不通过时会返回可读错误，修改标记保留，不会悄悄写出半成品；发布页同时显示中间产物路径、编译产物路径和本次集数统计。

## 9. 安全与注意事项

- **API Key**：优先用环境变量 `DEEPSEEK_API_KEY` / `MANJU_LLM_API_KEY` / `OPENAI_API_KEY`；在配置页临时输入的 Key 只存在 Studio 进程内存，不写 `config.json`。`--doctor` 会报告来源并警告旧版明文 Key。若 Key 曾出现在终端、日志或聊天里，请先吊销再换新。
- Studio 只读/写输入层，不启动/停止 ComfyUI、不管理显存、不触发出片。
- 若端口被占用，换 `--port`。
- 无产物时先跑「生成」，或用现有 `state/story/<小说名>/` 中间产物。

## 10. 前置产物说明

Studio 展示的均来自**当前小说** `state/story/<小说名>/` 中间产物：分镜读 `board_epNN.json`，资产读 `cast.json` / `art.json`，设定读 `outline.json`，关系读 `cast.json`。未生成前这些视图为空；可先在「生成」页跑一部小说，或切顶部「小说」下拉查看已有产物。

## 11. 与命令行的对应关系

Studio 不是另一套流水线，只是 `story_cli` 的可视化前端。常见操作对应如下：

| Studio 操作 | 等价命令行 |
|---|---|
| 生成页 → 开始生成（默认续跑） | `python -m manju.story_cli input\<小说>.txt --yes --force --resume` |
| 高级选项 → 先清临时工作层再重跑 | 在默认命令上加 `--clean`（Studio 仍保留 `--resume`；临时层清空后会从头生成，已固化成品不受影响） |
| 指定总集数 N | `--episodes N` |
| 每 N 章一集 | `--chapters-per-episode N` |
| 按剧情自动分集 | `--chapters-per-episode 0`（Studio 显式传入，覆盖旧配置） |
| 起始集 / 结束集 | `--from-episode N` / `--to-episode M` |
| 画幅 / 单集时长 | `--ratio 9:16` / `--duration 90` |
| 发布契约 → 重新编译 | 不调用模型；等价于编译 + gate/drama 审计后写入 `input/<小说名>/` |

因此两种方式可以随时切换：Studio 生成的中间产物，命令行 `--resume` 能直接复用；
命令行生成的产物，Studio 也能直接打开查看和修改。选择建议：

- **批量、服务器、CI、需要完整参数**：用命令行。
- **需要逐镜修改、可视化审阅、边看边调**：用 Studio。
