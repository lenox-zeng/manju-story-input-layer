# 模型服务商配置指南（OpenAI 兼容）

本流水线的文本模型走 **OpenAI 兼容协议**，不绑定 DeepSeek。默认配置 DeepSeek，
可切换任意 OpenAI 兼容服务商：官方 OpenAI、火山方舟·豆包、智谱 GLM、
Moonshot Kimi、通义千问、本地 vLLM/Ollama、自建统一网关等。

## 1. 配置字段（`config.json` → `llm` 段）

| 字段 | 含义 | 示例 |
|---|---|---|
| `provider` | 服务商标签（**仅作标签，不参与调用逻辑**，UI 显示/归档用） | `deepseek` / `doubao` / `custom` |
| `base_url` | OpenAI 兼容端点地址 | `https://api.deepseek.com/v1` |
| `model` | 模型名（必须是该服务商当前有效的名称） | `deepseek-flash` |
| `api_key` | 密钥；留空则读环境变量 | `sk-...` |

密钥优先级：环境变量 `MANJU_LLM_API_KEY` / `DEEPSEEK_API_KEY` / `OPENAI_API_KEY`
> `config.json` 的 `llm.api_key`。

## 2. 切换方式

1. **改 `config.json`**（推荐）：编辑 `llm` 段的 `provider` / `base_url` / `model` / `api_key`，重启生效；
2. **Studio 配置页**：服务商下拉 + `base_url` + `model` + Key（页面输入的 Key 只保留到本次 Studio 退出，长期使用请设环境变量）；
3. 环境变量只承载 Key，**改服务商端点必须用方式 1 或 2**。

## 3. 常见服务商对照

| 服务商 | `base_url` | 模型示例（以服务商当前文档为准） |
|---|---|---|
| DeepSeek（默认） | `https://api.deepseek.com/v1` | `deepseek-flash` / `deepseek-v4-pro` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` / `gpt-4o` |
| 火山方舟·豆包 | `https://ark.cn-beijing.volces.com/api/v3` | 推理接入点 `ep-xxxx` 或模型名 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` / `glm-4-plus` |
| Moonshot Kimi | `https://api.moonshot.cn/v1` | `kimi-k2` / `moonshot-v1-8k` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` / `qwen-max` |
| 本地 vLLM | `http://localhost:8000/v1` | 已部署模型名 |
| 本地 Ollama | `http://localhost:11434/v1` | 已拉取模型名 |
| 统一网关（One-API / new-api / LiteLLM） | 自部署地址 | 网关内配置的模型名 |

> 平台会不定期下线/更名模型，切换前请以服务商官方文档的模型列表为准。

## 4. 必须满足的约束（选型前先确认）

- **JSON 输出模式**：流水线所有阶段强制 `response_format={"type":"json_object"}`
  并要求严格 schema（解析失败会带着报错自动重问）。**所选模型必须支持
  JSON / structured outputs**。OpenAI、DeepSeek、豆包、智谱、Moonshot、
  通义（`qwen-plus` 及以上）一般支持；Ollama 等本地小模型的 OpenAI 兼容层
  支持有限，若某阶段反复重试，多半是模型 JSON 能力不足而非配置错误。
- **thinking 参数自动降级**：流水线默认携带 DeepSeek 风格 thinking 参数；
  若服务商拒绝该参数，会自动去掉并重试（首次可能多一次失败记录，之后不再携带）。
- **temperature 固定**：各阶段固定 `0.0`（长篇卷摘要 `0.2`），不通过配置调整，
  保证契约字段、镜头编号、续跑结果可复现。
- **上下文长度建议 ≥32k**：分集/分镜请求包含源文节选与历史产物，上下文过短
  会频繁截断触发重问。源文采样上限由 `llm.story_source_chars` 控制。

## 5. 切换后受影响项

- **费用统计**：Studio「LLM 调用日志」按 DeepSeek 官方价估算费用区间，换成
  其他服务商后金额仅供参考，实际以平台账单为准。
- **性能**：模型越弱 / 上下文越短，JSON 自修复重试越多、整集耗时越长。
  一次通过是最有效的提速手段。

## 6. 示例

切到 OpenAI 官方：

```json
"llm": {
  "provider": "openai",
  "base_url": "https://api.openai.com/v1",
  "model": "gpt-4o-mini",
  "api_key": "sk-...",
  "max_tokens": 8192
}
```

切到本地 vLLM（Key 可任意占位或留空）：

```json
"llm": {
  "provider": "custom",
  "base_url": "http://localhost:8000/v1",
  "model": "你的部署模型名",
  "api_key": "",
  "max_tokens": 8192
}
```
