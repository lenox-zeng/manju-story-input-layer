## 0. 评审须知

### 0.1 五个硬目标

| # | 目标 | 对文本契约的硬性要求 |
|---|---|---|
| 1 | 真人电影胶片质感 | 画风必须**受限槽位 + 禁词表**，不能由模型自由撰写 |
| 2 | 16:9 / 9:16 横竖屏双支持 | **可配置**：可只出一路，也可**同一次批跑同时产出多画幅**；每画幅独立构图，不是裁剪 |
| 3 | 多人同框 100% 不串脸、不串服装 | 角色设计区分度 + 逐镜走位/遮挡/服装态 |
| 4 | 上百集体量 | 不可变特征锁定 + 状态账本 + 跨集钩子链 |
| 5 | **换模型/换引擎不用改剧本资产** | 契约内**禁止出现任何模型名、节点名、算法名、采样器名、像素值**；引擎专属参数下沉到不向上游暴露的适配层（§9） |

> 承诺：**更换生成引擎（底模、人脸锁定工具、分区方式、插帧/配音链路、视频模型、甚至第三方商业 API）不构成契约版本变更，只改适配层，上游 plan/script/storyboard 一个字节都不用动。**

| # | 实测事实 | 新增字段 / 校验 |
|---|---|---|
| 1 | 首帧是中景、`prompt` 写 "close-up"，2.3 的 `condition_only` 不推近，直接**镜内硬切**（峰值帧差 36）；只删 "close-up" 无效（35.7），整段改写成首帧景别才消（12.5） | `prompt` 景别词 vs `framing[*].shot_size`：隔 ≥2 档 **block**，隔 1 档 warn（§8.2、§10） |
| 2 | LatentSync 只能放大已有嘴部动作，不能凭空造：2.3 原片嘴部信号 std 0.020（几乎闭嘴）时相关仅 0.46–0.49；带开口动作的 SH02 达 0.659 | 新增 `subjects[].speaking`：画内台词镜至少一名说话人 `true`（§8、§10.1） |

物件镜（靴子、手掌）与环境空镜**本来就没有人脸**，不应被"人脸占比"口径判成首帧偏差。

> 两个新字段均为**可选**。读取器遇到 `null` / 缺省时**跳过对应校验**，不清洗历史分镜。

### 0.10 下游接入约定（所有平台通用）

> 本节只写“任何实现平台都必须遵守”的部分。ComfyUI / Seedance / 其他平台的
> 节点、参数与工作流映射，写在各自的平台指南里；平台指南**不得复制或改写本节**。

**交接三件套**

| 交付物 | 作用 | 是否随平台变化 |
|---|---|---|
| 本契约 | 唯一数据标准：字段语义、校验规则、版本规则 | **不变** |
| 平台对接指南 | 该平台读取什么、怎么映射、不支持时怎么报错 | 每个平台一份 |
| 一份完整样例 | 可直接对照的真实产物 | 随契约版本 |

**读取与消费（平台无关）**

1. 读取顺序：`plan` → `script` → `storyboard` → `director` / `story_assets`。
   后两者是导演/资产辅助信息，不改变前三者的契约地位。
2. 时间统一用秒。`script.lines[].at_sec`、`script.narration[].at_sec`、
   `shot.start_sec` 都是**全集绝对时间**，不要另算一套相对时间。
3. `lines` 是台词，`narration` 是旁白。旁白**不做口型**、不进入 `audio`、
   不设置 `speaking=true`、不写 `dubbing="lipsync"`。
4. `transition_in` 只读取**场次第一镜**。`match_cut` / `action_bridge` /
   `sound_bridge` 是剪辑理由，不是视觉特效；bridge 类必须有 `anchor`。
5. `framing` 按**实际启用画幅**取。编译器会同时写 `9:16` 与 `16:9` 两套，
   但目标画幅由 `output.aspects.enabled` 决定；未启用的构图保留，不要丢弃。
6. A/B 层未知字段按 §1.3 处理；C 层 `hints` 可忽略且**不持久化**。
7. 不支持的能力必须**显式报错**，禁止静默降级（§4.5）。
8. 平台参数、节点名、工作流名、模型名只写在平台指南或适配层，
   **不得写回契约**。

**平台指南模板**（每份控制在 1–2 页）

1. 目标契约版本 + 指南版本 + 最后验证日期
2. 本平台读取哪些文件、读取顺序
3. 字段 → 平台参数/节点映射表
4. 本平台明确忽略的字段
5. 不支持能力的降级或报错策略
6. 用哪份样例、如何验收
7. 平台自己的工作流版本说明

**唯一事实来源**：字段语义以本契约为准。契约变更才升契约版本；平台升级只改平台指南。

**锚点语义**（详见 §8.4）

- `within_shot`：`at_sec ≥ shot.start_sec` 且 `at_sec + timing_sec ≤ shot.end_sec − 0.08`。
- `voiceover_span`：允许跨后续镜头，最多跨 `allow_span_shots` 个镜头（含锚镜）；
  `allow_cross_scene=false` 时所有跨越镜头必须同场。
- 旁白与任何台词、任何其他旁白之间至少留 **0.08s** 空隙，不允许重叠。
- `timing_sec ≥ ceil(汉字数 / 5)`，建议再留 10–20% 余量。
- 找不到满足条件的空位时，输入层必须**拆分 / 缩短 / 改锚点**，不要依赖实现层移动超过 `max_shift_sec`。
- **不新增** `allow_overlap_dialogue`：v10.3 仍不允许旁白压台词；要同时发声必须另做 ducking/混音，当前不开放。

**兼容性**：所有新字段在 schema 中均为**可选**，旧产物（v10.1 / v10.2，无锚点字段）继续可解析；但 gate 对"写了旁白却没有锚点字段 / 时间冲突"给 block，行为级向前收紧。

## 1. 技术解耦设计（核心）

### 1.1 三层分离

| 层 | 内容 | 谁写 | 变更频率 | 位置 |
|---|---|---|---|---|
| **L1 业务事实层** | 拍什么、谁出场、什么表情姿态、什么画幅、说什么话、多久 | 编剧 / 编辑工具 / LLM | **几乎不变** | A 层字段 |
| **L2 能力声明层** | 这一镜对生成器的**抽象能力诉求**（像不像、稳不稳、要不要严格分区） | 编剧可留空，流水线可补 | 低 | B 层 `requirements` |
| **L3 引擎提示层** | 某个具体引擎才懂的参数 | **只由适配层写** | 随引擎换 | C 层 `hints` |

**关键不变式**
1. L1 只描述**人类摄影指导能听懂的事实**——任何人拿到 L1 都能拍，哪怕不用 AI。
2. L2 只描述**"要多像、要多稳"这种可被任何引擎翻译的诉求**，不含实现方式。
3. L3 **允许**引擎专属，但**永远不是必填**；缺失时适配层必须能自行推导，或明确报"不支持"。

### 1.2 命名禁令（硬性）

**禁止出现在 A 层与 B 层**（字段名与字段值**同时**扫描）：

1. 模型名 / 权重名 / LoRA 名（任何具体 checkpoint、任何具体工具）
2. 节点名 / 工作流节点 ID
3. **算法名 / 链路名**（任何具体插帧算法、人脸锁定算法、分区算法、配音链路）
4. 采样器名、调度器名、CFG / steps / denoise 等采样参数
5. **像素数值**（宽高、分辨率）—— **唯一例外见下方「例外」段**
6. 提示词工程术语（`masterpiece` / `best quality` 一类），以及**成串的模型负面表**（判定规则见 §1.2.2）

> **例外（按性质划分，不按清单）**：禁令针对的是**渲染参数**（怎么算出来），不针对**业务事实**（拍什么）与**验收阈值**（达到什么算合格）。
> - ✅ 允许：`visual_bible` 的 `film_stock` / `lens` / `lighting` / `palette` / `texture` / `contrast` / `skin_tone` / `motion_character` / `depth_style` —— 摄影事实。
> - ✅ 允许：`output.min_resolution` —— **验收阈值**：低于此即不合格。
> - ❌ 禁止：`max_resolution`（渲染参数，无业务意义）、`steps` / `cfg` / `sampler` / `denoise` 等。

#### 1.2.1 两类禁令，两种执法方式

| 类别 | 内容 | 执法方式 |
|---|---|---|
| **机械可判** | 像素值、采样器名/参数名、节点 ID、成串负面表 | 校验器**内置规则**直接判定，**无需词表** |
| **需词表** | 模型名 / 权重名 / LoRA 名 / 算法名 / 链路名 | 校验器**加载适配层声明的黑名单** |

**词表的维护归属**
- 黑名单**归适配层仓库维护**——适配层认识所有已知引擎，天然能提供该名单。
- **契约不维护词表本身**，只定义一条义务：*适配层的清单必须随其支持的引擎同步更新*。
- 校验器启动时加载适配层声明的黑名单。
- **陌生技术名词兜底**：未命中已知黑名单、但形如引擎/模型名的英文技术名词 → **warn**，人工确认。

> 不加这条兜底，新引擎名就能悄悄藏进 A 层字段值而不被扫描发现——这正是解耦被逐渐侵蚀的无声形态。

#### 1.2.2 「成串负面表」的可判定定义

- 判定规则：同一字段值内出现 **≥3 个**（逗号或空格分隔的）缺陷/质量类词（`blurry` / `lowres` / `bad anatomy` / `watermark` / `deformed` / `oversaturated` / `extra limbs` 等）→ 判定为负面表，**block**。
- 作用：`negative_prompt` 已移出 A 层（§8.1），此规则用于拦截"重新把引擎负面表写回业务资产"。

**扫描规则（v10.1 收紧）**
- 扫描范围 = **所有 A 层与 B 层字段的"值"**，**含自由文本字段**：`prompt`、`composition`、`desc_en`、`desc_cn`、`motion`、`keyframe`、`action`、`emotion` 等。
- **不只扫字段名**——引擎词完全可以藏进 `prompt` 的值里。
- 命中即 **block**。
- C 层 `hints` 不扫描（那是引擎自己的地盘）。

> 这条同时是"防止引擎参数伪装成业务字段写进 A 层"的机械手段（回应第二轮问题 7）。

### 1.3 字段三级分类与未知字段策略

| 级别 | 位置 | Schema 策略 | 未知字段 | 兼容承诺 |
|---|---|---|---|---|
| **A 业务事实** | 顶层业务字段 | `extra = "forbid"` | **block** | 永久稳定，**只增不改**；语义变更须升大版本 |
| **B 能力声明** | `requirements` | `extra = "forbid"` + 值域枚举 | **block** | 稳定；可新增键/枚举值（升小版本） |
| **C 引擎提示** | `hints` | `extra = "allow"` | 忽略 + WARN | **无兼容承诺**，可整体丢弃 |

### 1.4 版本演进规则

- `schema_version` 必填，格式 `"v<major>"` 或 `"v<major>.<minor>"`（如 `"v10.1"`）。
- **大版本**：A 层字段增删或语义变更 → 需评审 + 迁移脚本 + 存量回归。
- **小版本**：仅 B 层新增键/枚举值、或 C 层变化 → 无需迁移。
- **更换生成引擎 → 不构成任何版本变更。** 这是对"技术解耦"的可验证承诺。
- 读取器接受 `v10` / `v10.1` / `v10.2`（同一大版本）；产出**必须**写 `"v10.2"`。不做永久双读。
- `v10.2` 是对 `v10.1` 的**小版本**：只新增可选字段 + 收紧三条文本校验，旧文档可直接被读取器和内部门禁接受。

## 3. 四条贯穿铁律

1. **画风只在 `plan.visual_bible`。** 其他文件的任何字段都不得再描述画风。
2. **`desc_en` 只写人。** 禁止出现任何场景/背景/环境词（中英文均禁）。
3. **不可变与可变必须分离。** 脸、发型、瞳色、身高、永久标记 = 不可变，进 `identity_lock`；服装、伤势、道具 = 可变，进 `wardrobe_states` 与状态账本。
4. **只写事实，不写引擎。** 任何字段（名与值）都不得描述"用哪个模型、哪个节点、哪个算法、多少像素"来实现（§1.2）。

## 4. 通用能力声明（`requirements`）

### 4.1 词汇表

| 能力键 | 允许值 | 含义 | 内置默认 |
|---|---|---|---|
| `identity_fidelity` | `low` / `medium` / `high` / `locked` | 与角色参考的相似度。`locked` = 必须与参考完全一致 | `high` |
| `wardrobe_fidelity` | `low` / `medium` / `high` | 服装与 `wardrobe_state` 描述的一致度 | `high` |
| `spatial_control` | `none` / `loose` / `strict` | 是否严格按 `framing.subjects` 摆放人物 | 同框 ≥2 人 → `strict`，否则 `none` |
| `temporal_stability` | `none` / `shot` / `scene` / `series` | 稳定度范围：镜内帧间 / 镜间 / 全集 / 全剧 | `scene` |
| `quality_tier` | `draft` / `standard` / `hero` | 质量档位，直接影响成本 | 按 `scene_type` 推导（§7.2） |
| `multi_subject_strategy` | `auto` / `joint` / `per_subject` / `hybrid` | 多人同框策略：整体一次 / 逐人再合成 / 混合 | plan 级 `auto`；**同框 ≥2 人时必须显式填写**（§4.4） |
| `interaction` | `none` / `contact` / `entangled` | 人物间是否存在肢体接触及强度。`entangled`（缠斗/拥抱）难度最高 | `none` |
| `hand_precision` | `default` / `hero` | 手部为画面重点（手部特写、持物特写） | `default` |
| `text_render` | `none` / `simple` / `dense` | 画面内需渲染文字（招牌、屏幕、书信） | `none` |
| `interpolation` | `none` / `standard` / `high` | 是否需要补帧及其档位 | plan 级 `standard` |
| `dubbing` | `none` / `auto` / `lipsync` | 是否需要配音处理及是否要求口型对齐 | plan 级 `auto` |

> 全部为**能力诉求**，不含任何实现方式。任何引擎必须能给出自己的实现，或明确报"不支持"。

### 4.2 合并语义：**键级合并**（v10.1 新增，关键）

`requirements` 可出现在 **plan 级 / script 级 / storyboard 镜头级**。

> **规则：键级合并，缺省继承最近上级。禁止整体替换。**

解析顺序：`镜头级 → script 级 → plan 级 → 内置默认`，**逐键**取第一个出现的值。

- ❌ **禁止**：镜头级写了 `{"quality_tier":"hero"}` 就丢弃 plan 级的 `identity_fidelity: locked`。
- ✅ **正确**：该镜 `quality_tier = hero`，`identity_fidelity` 仍继承 plan 的 `locked`。

> 若采用整体替换，shot 少写一个键就静默丢一个 plan 级声明——**这正是 v9 静默降级事故的翻版**，必须靠本规则堵死。

### 4.3 生效链必须可审计（v10.1 新增）

> 适配层必须为每个镜头输出**生效链**：每个能力键的**最终生效值**及其**来源层级**（`shot` / `script` / `plan` / `default`）。

- 该记录写入**运行时报告**，**不写入资产文件**（§9.4）。
- 校验时比对"声明链"与"生效链"：同一键出现两个不同值即为缺陷。
- 这是机械拦截"**声明 `locked` 却按 `high` 执行**"的唯一可行手段——不依赖适配层自查自评。

**达成判定依据（防住"声称达成"）**

生效链能防住"**主动写不一致**"，但防不住"**声称达成**"——适配层把 `locked` 的实现定义成与 `high` 完全相同，外部无从判断。

> **契约义务**：适配层对每个 `locked` / `strict` 的产出，**必须在运行时报告中声明其达成判定依据**（例：`"identity_similarity >= 0.85"` 或 `"coord_deviation <= 0.05"`）。

- **不指定度量方式**（那是实现层的事），只强制"**说清楚你是凭什么判定达成的**"，使审计可追。
- 高承诺值声明缺少判定依据 → **block**。

### 4.4 禁止用 `auto` 兜底高风险场景

- `multi_subject_strategy: auto` **仅允许出现在 plan 级**。
- **同框 ≥2 人的镜头，`multi_subject_strategy` 必须显式填写**，不得依赖推导。
- 注意：plan 级写 `auto` **不等于**镜头级已声明。键级合并后，若某镜的
  生效值仍是 `auto`（或三层都缺省），该镜视为**未声明**，gate 报
  `struct.multi_subject_undeclared`（block）。
- 编译侧义务：同框 ≥2 人时，产出方必须把 `joint` / `per_subject` / `hybrid`
  写进 `storyboard.shots[].requirements`；不允许把 plan 的 `auto` 原样透传。
- 理由：`auto` 由适配层决定，若推导结果低于实际需要，**无人察觉**——`auto` 是静默降级的温床。

### 4.5 不支持必须报错，不许静默降级

> 适配层必须为实际出现的**每一个 `requirements` 取值**提供实现，或明确返回"不支持"。
>
> "声明了 `locked` 却按 `high` 执行""声明了 `strict` 却按 `loose` 执行"，一律判定为 **block 级缺陷**，必须在启动自检中拦下。

这是 v9 `img2img_multi` 事故（契约里写了、枚举里有、函数写好了，但渲染器无对应分支，实际被静默降级）的**机制性解药**——问题不在字段少，而在"声明与执行不一致时无人报警"。

### 5.1 受限槽位枚举

| 槽位 | 允许值 | 校验级别 |
|---|---|---|
| `medium` | 固定 `photorealistic cinematic film still` | block |
| `film_stock` | `Kodak Vision3 500T` / `Kodak Portra 400` / `Fuji Eterna 500T` / `CineStill 800T` / `Ilford HP5 B&W` | block |
| `lens` | `24mm wide` / `35mm` / `50mm` / `85mm portrait` / `35mm anamorphic` | block |
| `contrast` `skin_tone` `motion_character` `depth_style` `lighting` `palette` `texture` | 摄影 / 色彩 / 材质术语 | **warn**（非白名单词） |

> **为什么自由槽位是 warn 不是 block**：白名单不可能穷尽合法摄影术语，硬报错会误伤；画风发散的真实病根是**源头不唯一**（分镜层偷写画风）与**权威字段过期**，不是漏词。
>
> **配套要求**：warn 必须进入**每周回归报告**并量化跟踪，否则 warn 会累积成"已知但不管"的债务。

### 5.2 画风编译（替换 v9 的"覆盖"机制）

- **权威 = 槽位**。适配层从槽位编译出目标引擎所需的条件输入（文本串、风格参考图、条件向量……视引擎而定）。
- `storyboard.style_suffix` **保留字段但必须为空**；非空即 block。
- `visual_bible.style_ref_en` **可选**：填了则作为文本逃生舱，仍须过 forbidden 扫描；不填则完全由槽位编译。
- 槽位值命中 `forbidden`（含复合词与中文词）→ **block，整份 plan 不合格**。

### 5.3 `desc_en` 禁词与中英一致性

**禁词（中英文均扫）**
`alley` / `street` / `background` / `interior` / `room` / `city` / `night` / `rain` / `lantern` / `shop` / `eaves` / `小巷` / `街道` / `背景` / `室内` / `房间` / `城市` / `夜` / `雨` / `灯笼` / `店铺` / `屋檐` 等一切**场景与背景词**。

> 原因：定妆图要求"纯色背景、全身、正面"，场景词会与之直接冲突，导致定妆图背景失控、被裁切。场景归 `storyboard.prompt`，不归角色描述。
>
> 校验级别：`desc_en` 命中 → **block**（机械可判定，且是历史上最严重的污染源）；`desc_cn` 命中 → **warn**（中文描述允许保留氛围词供人阅读）。

**中英一致性（v10.1 新增）**
- `desc_en` 为**图像生成的唯一权威**。
- `desc_cn` 与 `desc_en` 的**外貌要素**必须一致（发型、瞳色、体型、标记物）。不一致 → **warn**，人工确认。

## 6. 双画幅规范（16:9 / 9:16）

### 6.1 需求

- **可配置**：能只出 16:9、只出 9:16、或两者都出。
- **可同时**：一次批跑同时产出全部启用画幅（`output.simultaneous`）。
- **构图独立**：每个画幅有自己的构图。竖屏不是横屏切一刀。
- **可逐镜覆盖**：允许个别镜头只出某一路（如空镜只出 16:9）。

> **本包实现现状**：`story_cli` 单次运行通过 `--ratio` 选择一个目标画幅，
> 因而 `plan.output.aspects.enabled` 当前只写一个值；但编译器仍为每个镜头写
> `9:16` 与 `16:9` 两套 `framing`。真正的多画幅同时批跑属于下游运行时能力，
> 不改变本契约的字段结构。

### 6.2 配置层级（就近覆盖）

| 层级 | 字段 | 说明 |
|---|---|---|
| plan 级 | `output.aspects` | 全剧默认：启用哪些、主画幅、派生策略、分辨率策略 |
| script 级 | `aspects_override`（可选） | 按集覆盖 |
| **shot 级** | `aspect_overrides`（可选） | 按镜覆盖，如 `{"9:16":"reframe_recompose"}` 或 `{"enabled":["16:9"]}` |
| 运行时 CLI | `--ratio 16:9` / `--ratio 9:16`（本包 `story_cli`） | 单次运行选择一个目标画幅；下游若提供多画幅批跑参数，属其运行时配置，**不写入资产文件** |

### 6.3 四种派生策略（v10.1 由 3 种拆为 4 种）

| 策略 | 本质 | 能否换景别/机位 | 能否增减角色 | 一致性 | 成本 |
|---|---|---|---|---|---|
| `independent` | 各画幅独立生成 | ✅ | ✅ | 中（须共享身份输入与 seed 基） | ×N |
| `reframe_crop` | 主图**扩边 + 重排**，构图同源（人物比例朝向不变） | ❌ | ❌ | **最高** | ≈×1 |
| `reframe_recompose` | 允许**局部重绘**换机位 / 去角色 | ✅（受重绘质量限制） | 去角色易、加角色难 | 中高（重绘区仍是 inpaint 质量） | ≈×1.2 |
| `crop` | 直接裁切主画幅 | ❌ | ❌ | 高（同一张图） | ×0 |

> **v10.1 关键澄清**：v10 把"扩图重排"与"换机位"混为一谈，导致承诺自相矛盾。**`reframe_crop` 做不到换景别、换机位、角色增减。** 凡涉及这三者的派生画幅，本质只能是 `independent` 或 `reframe_recompose`。

**选型指引**
- 竖屏仅需**收窄取景、重排人物** → `reframe_crop`（保脸，最省）。
- 竖屏需要**换机位/换景别**（如横屏中景 → 竖屏过肩特写）→ `reframe_recompose` 或 `independent`。
- 空镜 / 无人物的纯背景镜 → `crop`（可放宽为"**无人物或人物无肢体错位风险**的镜头"）。
- 关键 hero 镜、双画幅都要最好的 → `independent`。

### 6.4 一致性硬约束（block 级）

1. 同一镜头的所有画幅**必须共用同一身份输入与同一 seed 基**。
2. `reframe_crop` / `reframe_recompose` / `crop` 派生的画幅**必须记录 `derived_from`**（源画幅 + 源资产引用）。缺失即 **block**（返工溯源锚点，不可降级）。
3. **声明某派生策略却实际走独立重新生成 = block**（声明—执行不一致）。
4. 画幅之间 `subjects` **允许不同**（可以有人出画），但同一 `char_id` 的 `identity_lock` 与 `wardrobe_state` **必须一致**（block）。
5. **（warn）** shot 级 `aspect_overrides` 若使某画幅的一致性等级**低于 plan 默认**（如 plan `reframe_crop` → shot `independent`），产生告警，需人工确认。

### 6.5 `framing` 字段规范

```json
"framing": {
  "16:9": {
    "shot_size": "medium",
    "subject_type": "character",
    "composition": "三人横向铺开，C1 左三分之一，C2 中心偏后，C3 右后景",
    "subjects": [
      {"char":"C1","pos":"left","height_level":"mid","depth":"foreground",
       "facing":"toward_other","occludes":[]},
      {"char":"C2","pos":"center","height_level":"mid","depth":"midground",
       "facing":"toward_other","occludes":[]},
      {"char":"C3","pos":"right","height_level":"low","depth":"background",
       "facing":"toward_camera","occludes":[]}
    ]
  },
  "9:16": {
    "shot_size": "close_up",
    "composition": "竖幅收窄并换机位，过肩特写，只保留 C1 与 C2，C3 出画",
    "overlap_order": ["C1","C2"],
    "subjects": [
      {"char":"C1","pos":"center_left","height_level":"mid","depth":"foreground",
       "facing":"profile_right","occludes":["C2"]},
      {"char":"C2","pos":"center_right","height_level":"mid","depth":"midground",
       "facing":"profile_left","occludes":[]}
    ]
  }
}
```

> **本镜的 `aspect_overrides` 必须为 `{"9:16":"reframe_recompose"}`** ——因为竖屏换了机位与景别（中景 → 过肩特写）且 C3 出画，`reframe_crop` 做不到（§6.3）。这正是 v10 示例自相矛盾之处，v10.1 已修正。

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `shot_size` | 是 | `extreme_wide` / `wide` / `full` / `medium` / `medium_close` / `close_up` / `extreme_close_up` | 景别 |
| `subject_type` | 否 | `character` / `object` / `environment` | **v10.2 新增**：本画幅主体类别。`character`=有人物；`object`=靴子/手掌/道具特写；`environment`=空镜/远景环境。缺省 = 旧分镜未声明，不做人脸占比口径校验 |
| `composition` | 是 | 自然语言（中文） | 人类可读的构图描述 |
| `overlap_order` | 否 | char_id 数组（前 → 后） | 表达完整的前后遮挡顺序。**交叠 ≥3 人时建议填写**；2 人时 `occludes` 已可唯一确定，也可填写，但必须与之一致（见下方优先级规则） |
| `subjects[].char` | 是 | char_id | 必须 ∈ plan.characters（block） |
| `subjects[].pos` | 是 | `far_left` / `left` / `center_left` / `center` / `center_right` / `right` / `far_right` | **语义化水平位置**（替代 v9 的 0-1 浮点数） |
| `subjects[].height_level` | 否 | `low` / `mid` / `high` | **v10.1 新增**：垂直层，表达阶梯站位、高低落座、俯拍分布。默认 `mid` |
| `subjects[].depth` | 是 | `foreground` / `midground` / `background` | 前后景 |
| `subjects[].facing` | 否 | `toward_camera` / `away` / `profile_left` / `profile_right` / `toward_other` | **v10.1 新增**，与 `space_map.facing` 语义统一 |
| `subjects[].occludes` | 否 | char_id 数组 | **只填直接被遮挡者**；适配层递归展开完整遮挡链；**禁止循环**（block） |
| `subjects[].offscreen` | 否 | 布尔，默认 `false` | **v10.1 新增**：画外角色（有声音/被提及但不在画面） |
| `subjects[].mirrored` | 否 | 布尔，默认 `false` | **v10.1 新增**：镜面/倒影中的虚像 |
| `camera_recipe` | 否 | 对象 | **v10.4 新增**（P0.5 摄影配方）：`lens_mm`（24/35/50/85）+ `depth_of_field`（shallow/moderate/deep）+ `light_key`（光源方向+质量+色温一句话）+ `light_quality`（diffused/hard/atmospheric）+ `composition`（可选）。只写本镜**摄影事实**，不写画风（画风唯一来源是 VisualBible）；引擎不给光照就默认平光。缺省 = 旧产物未声明，不做配方校验 |

**`overlap_order` 与 `occludes` 的优先级**

- 两者都能表达前后遮挡关系，**同时提供时必须一致**。
- `overlap_order` 提供时**以它为准**（它是完整的前后顺序）；`occludes` 表达的是**直接遮挡**关系。
- 二者矛盾 → **block**。

> **v10.1 说明**：`pos` + `depth` 只能表达"左右 + 前后 3 档"，无法表达垂直分布、纵深列队、镜像、画外。新增字段全部是**人类场记本能理解的摄影事实**，不违反命名禁令，也**不把精度还原的责任全押在 `composition` 的自然语言解析上**。它们均为**可选**，编剧可不填。

**为什么用 `pos` 替代 `x`**（D1）
- `x: 0.25` 是**引擎参数**（只有做潜空间分区的引擎才需要），换引擎即失效 → 违反技术解耦。
- `pos: "left"` 是**摄影事实**，任何引擎都能翻译成自己的参数。
- 编剧写 `left` 的出错率远低于写 `0.25`，第一轮评审提出的"编剧手写浮点数负担重"从根上消失。
- 引擎若需要精确 `x`，适配层从 `pos` + 其余事实字段推导，写入 C 层 `hints`，**不污染 A 层**。

### 6.6 分辨率策略

- `resolution_policy`：`engine_default`（适配层按引擎友好桶输出）或 `explicit`（在 `output` 中写明）。
- **A 层禁止出现像素值**（§1.2），唯一例外是 `output.min_resolution`——它是**业务可接受下限**（"再低就不合格"），不是实现参数。
- 适配层产出的实际尺寸**不得低于** `min_resolution`；低于即 block。

### 7.1 台词时间轴规则

**90 秒结构要求（v10.3，输入层提交前自检）**

| 指标 | 要求 |
|---|---|
| 总时长 | `90.0s`（允许 ±0.5s 内对齐） |
| 场景数 | 6–10 |
| 镜头数 | 40–55 |
| 台词句数 | 6–12 |
| 平均镜头时长 | ≤ 2.6s |
| 单镜最长 | ≤ 4.2s |
| 旁白数量 | 每场 0–2 条，全片 ≤ 8 条 |

> 这是**目标结构**，不是硬 block（内容密度优先于数字配额）；超过时先审视
> 是否有可拆的蒙太奇/过渡镜，其次才是放宽配额。实现层渲染预算按 90s 推导。

**默认语速 4.5 字/秒**（对应 `story.chars_per_second = 4.5`），可被场级 `speech_cps` 覆盖。

**情绪语速建议区间**（v10.1 新增，供编剧参考，非强制）

| 情绪 | 建议 cps |
|---|---|
| 低语 / 哽咽 / 沉默戏 | 2.5 – 3.5 |
| 常态对白 | 4.0 – 5.0 |
| 急促 / 争辩 | 5.5 – 6.5 |
| 嘶吼 / 呐喊 | 6.0 – 7.5（且 `timing_sec` 应留呼吸余量） |

**P0-S2 情绪语速（2026-10-23 落地）**：compile 按场级台词 `delivery`/场 `mood` 推 `speech_cps`（渲染端 TTS/口型语速，落上表区间），不再恒 4.5。**台词容量校验统一按生成口径默认 4.5**（镜头时长即按默认语速生成），情绪语速对镜头时长的反哺（拍级语速→镜头时长联动）属后续 P1。

**校验（block）**
- `ceil(len(text) / cps) ≤ timing_sec`（`cps` 取场级覆盖值或默认 4.5）。不满足要么砍字、要么加时长。
- `at_sec` 必须落在所属镜头区间内（`start_sec ≤ at_sec < start_sec + duration_sec`）。
- 同一角色同一镜头内多句台词 `at_sec` 不得重叠。
- **字幕、TTS、口型三处共用这份时间轴**，是唯一事实来源，不要另写一份。

**storyboard 的 `audio` 台词书写规范（v10.2 明确）**

`audio` 是自由文本，但画内/画外台词必须用**可机械解析**的标签写法，否则门禁无法判断哪句要口型：

```
同期（C1，画内）：你到底是谁；画外（C2，无口型）：不重要
```

- 每句一个标签；句间用 `；`。
- `画内` = 说话人在画面里且需要口型（同时应在该镜 `requirements.dubbing` 写 `lipsync`）。
- `无口型` = 画外台词/回忆中的台词，不做口型。
- **注意区分**：`无口型` 仍是 `audio` 里的台词（有人声、有说话人）；解释性旁白与角色内心独白不走 `audio`，而写入结构化的 `scene.narration` / `shot.narration`（见 §7、§8），不做口型。
- 台词正文避免再出现 `同期（` / `画外（` 字样；分号可保留（解析器按下一个标签切分）。

**镜头段长校验（v10.2 新增）**

- 可用帧数 = `((int(duration_sec × fps) − 1) // 8) × 8 + 1`（LTX `8n+1`，向下取整）。
- 需求帧数 = `ceil(len(text) / cps × fps) + 2`（2 帧给取整和 LatentSync 留余量）。
- 需求 > 可用，但按 `atempo ≤ 1.5` 压缩后可装下 → **warn**（配音会加速，非设计意图）。
- 压缩到 `atempo = 1.5` 仍装不下 → **block**。不要指望 LatentSync 补时长。

### 7.2 `scene_type` → 质量档位的默认映射（可被 `requirements.quality_tier` 覆盖）

| `scene_type` 含 | 默认 `quality_tier` | 理由 |
|---|---|---|
| `action` | `hero` | 动作 + 多人同框最易崩脸，必须最高档 |
| `group_dialogue` | `hero` | 群像，同框人数最多 |
| `dialogue` 且同框 ≥2 人 | `standard` | 需要分区，但动作幅度小 |
| `dialogue` 且单人 | `draft` | 快档足够 |
| `transition` / `montage` | `draft` | 空镜、过场 |

> 这是**默认推导**，不是硬绑定。且按 §4.4，**同框 ≥2 人时 `multi_subject_strategy` 必须显式声明**，不得依赖推导。

### 7.3 闪回/幻象场与状态账本的关系

> **`character_flags` 含 `flashback` 或 `vision` 的场次，其角色状态变化不计入 `continuity_ledger` 的时间线链路。**

- 闪回中的服装、伤势、道具属于**过去时间线**，不得覆盖当前时间线的状态。
- `continuity_ledger` 只记录**时间线内**（当前时间）的变化。
- §10.1 的"本集末态 = 下集初态"校验**只看时间线内变化**：若某集结尾是闪回，末态取该闪回**之前**最近的时间线内状态。

> 不加此规则，闪回会因为"穿旧衣服"被记成换装，进而让跨集校验误报，并**连锁污染后续所有集**。

### 7.4 `continuity_ledger` 内层键约定（机械校验用）

- 内层键**必须与 `plan.continuity.mutable` 的取值同名**。权威是**该系列 plan 里实际写的那几个键**，不是本节或 §5 示例里的字面写法 —— 不同系列可以叫 `wardrobe_state` 或 `wardrobe_states`，只要 plan 与 script 一致即可。
- §7 示例中的 `换装` / `获得道具` / `关系变化` 是同一语义的口语写法，**机械校验只认规范键名**；适配层读到别名时按下表归一后落库，不得两种写法并存：

  | 口语别名 | 归一目标（取 `continuity.mutable` 中存在的那个） |
  |---|---|
  | `换装` | `wardrobe_state` / `wardrobe_states`（单复数视为同一键） |
  | `获得道具` / `失去道具` | `持有道具` |
  | `人物关系` / `关系变化` | 二者互为别名，取 plan 里实际用的那个 |

- 归不到 `continuity.mutable` 的内层键 → block；外层角色键必须是 `plan.characters` 中的 `char_id`。
- 值的形态：服装态键为 `state_id` 字符串（须在该角色状态库内），`伤势` / 关系类键为字符串，含"道具"的键为字符串数组（**空数组 = 明确"无道具"，与"未记录"不同**）。`null` 一律 block —— 它和"未记录"没法区分。
- 只记录**时间线内**变化（§7.3）；§10.1 跨集校验逐键比对归一后的键名。
- 账本是**末态快照**，不是 diff：本集没变的角色状态**也要原样抄一遍**，否则下集的"初态"无从取值，跨集校验会误报。

### 8.2 易混字段职责边界与 `prompt` 权威范围（v10.1 新增）

| 字段 | 回答的问题 | 示例 |
|---|---|---|

| `camera_move` | 摄影机**是否运动、怎么动**（`null` = 无运动） | `push_in` / `pull_out` / `pan_left` / `tilt_up` / `track` |
| `motion` | **画面内的被摄主体**在做什么 | `C1 raises right hand slowly` |
| `ref_characters` | 本镜**画面内实际出现**哪些角色（含道具/局部代指） | `["C1","C2"]`；**画外角色用 `subjects[].offscreen=true`，不入本字段** |

> 三者互不替代：`camera: "handheld"` + `camera_move: null` + `motion: "C1 起身"` 是合法组合。

**`prompt` 的权威范围（v10.1 补强）**

`prompt` 是画面的**文本形态**，其权威**仅限文本描述范畴**：

| 冲突对象 | 谁优先 | 级别 |
|---|---|---|
| `segments[].text` | **`prompt`** | warn |
| `framing` / `subjects` / `motion` / `ref_characters`（**结构化事实**） | **结构化字段** | warn |
| `prompt` 中的景别词 vs `framing[*].shot_size` | **`framing`** | 隔 ≥2 档 **block**；隔 1 档 warn（v10.2） |

> **凡涉及"角色是谁、站在哪、什么景别、在做什么动作"，一律以结构化字段为准。**
>
> **v10.2 例外说明**：景别冲突从 warn 升级为 block，是因为它不是"描述与结构谁优先"的编辑问题，
> 而是**生成指令自相矛盾**。LTX-2.3 `condition_only` 不会推近/拉远，只会用镜内硬切同时满足两边；
> 实测已复现（SH02：中景首帧 + close-up 提示词 → 第 7 帧硬切）。只改一个词无效，必须整段对齐。

理由：结构化字段是机器可校验、且**驱动多人分区与防串脸**的直接依据。若放任 `prompt` 凌驾其上，**改一句散文就能悄悄推翻站位**——等于在契约最要害的地方留了第二个真相源，恰是本契约要消灭的病。

`segments[].text` 为可选分段细化，仅用于长镜头分段生成；与 `prompt` 冲突时以 `prompt` 为准。禁止把两者写成互相矛盾的画面描述。

### 8.3 时长算账与阶段化子分镜（2026-10-30 扩展，全部可选，旧文件继续可用）

**背景**：单镜时长若按默认档位瞎填、且一镜塞多个动作，实现层按统一秒数渲染必然"放不下"（实测 SH03 2.47s 塞 3 个动作）。本扩展让输入层产出**可复核的时长依据**与**一段一动作的阶段化子分镜**，由适配层按引擎能力消费。

**新增字段（均为可选）**：

| 字段 | 所属 | 说明 |
|---|---|---|
| `duration_basis` | `shots[]` | 中文时长算账过程，如 `动作3拍×1.5s=4.5s；台词0字；景别下限1.5s；取大4.5s→对齐5s`。供人工复核与调参，非引擎参数 |
| `phase` | `segments[]` | 段位：`start` / `mid` / `end`（可选，默认 `mid`） |
| `beat` | `segments[]` | 该段的中文动作要点（供人工核对） |
| `time_range` | `segments[]` | `[起秒, 止秒]`；段区间**连续、不重叠**，段秒数和 = 整镜 `duration_sec` |
| `camera_phase` | `segments[]` | 该段内的运镜阶段；继承整镜 `camera_move`，**不改变"每镜必须有运镜"约束** |
| `state_in` / `state_out` | `segments[]` | 段级承接：`state_out` → 下一段 `state_in`，段间不许动作断裂/瞬移 |
| `keyframe` | `segments[]` | 本段是否作为条件注入帧（LTX 中段注入 / Seedance 尾帧串联） |
| `frame_hint` | `segments[]` | 目标帧提示：`"first"` / `"last"` / 具体帧号（LTX 按 `8n+1`） |
| `source` | `segments[]` | 段来源（可选）：`"fallback"` = compile 确定性动作组拆分（非逐动作语义拆分，审计豁免一段一动作语义检查）；缺省/`null` = 分镜层 LLM 生成 |

**阶段化纪律**：
- 一段**一个主动作**（起点→过程→结果）；动作数 >1 的镜必须拆段或拆镜，不得硬塞
- 台词只影响该段时长，**台词文本一字不改**（key_lines 约束不受影响）
- 引擎映射走配置，不写两套逻辑：LTX → `frame_hint` 中段关键帧注入（LTXVAddGuide）；Seedance → 首段拼 `prompt`、末段 `keyframe=true` 做尾帧（`return_last_frame`）；万相/可灵 → 段转"镜头序号+时间戳+分镜内容"多镜头 prompt

**时长下限（引擎配置参数，见 `manju/story/engines.py`）**：
`单镜时长 ≥ max(景别下限[特写1.5/中景3/远景4]s, 动作节拍数×action_seconds_per_beat(1.5)s, 台词字数/chars_per_second + 句数×pause_seconds_per_line(0.7)s)`，再向上对齐 `duration_tiers`（comfyui=[2,3,4]s 对应 25fps 49/73/97 帧；seedance 不设档位取整秒）。

### 8.4 旁白时间契约（v10.3 新增，唯一权威在 `shots[].narration`）

**NarrationLine 锚点字段**（schema 中均为可选，行为校验在 gate）：

| 字段 | 类型 | 必填语义 | 默认 | 说明 |
|---|---|---|---|---|
| `anchor_mode` | `"within_shot"` / `"voiceover_span"` | 有旁白必填 | 无 | 旁白完整落在本镜内，还是允许跨镜头 |
| `shot_id` | string | 有旁白必填 | 无 | 旁白锚定的镜头；必须是真实存在的 shot |
| `at_sec` | number | 有旁白必填 | 无 | 成片**绝对**起点（秒），不是场景相对时间 |
| `timing_sec` | number | 有旁白必填 | 无 | 预期时长（秒），必须能装下文本 |
| `allow_span_shots` | integer | 仅 `voiceover_span` | 1 | 最多跨几个镜头（含锚镜） |
| `allow_cross_scene` | boolean | 否 | false | 是否允许跨场景；默认禁止 |
| `max_shift_sec` | number | 否 | 3.0 | 允许实现层前后微调的最大秒数 |

`kind` / `speaker` / `text` / `delivery` / `voice` / `emotion` 保持 v10.2 不变。
**不新增** `allow_overlap_dialogue`：仍不允许旁白压台词；要同时发声必须另做 ducking/混音，当前不开放。

**两种锚点模式**

- `within_shot`：`at_sec ≥ shot.start_sec` 且 `at_sec + timing_sec ≤ shot.end_sec − 0.08`。
  适合：镜头内独白、短旁白、与画面动作严格同步的说明。
- `voiceover_span`：允许跨到后续镜头，最多跨 `allow_span_shots` 个镜头：
  `at_sec ≥ anchor_shot.start_sec`；`at_sec + timing_sec ≤ end_sec_of(anchor_shot + allow_span_shots − 1)`；
  `allow_cross_scene=false` 时，所有跨越的镜头必须在同一场。
  适合：开场旁白、蒙太奇、跨镜叙事旁白。

**必须遵守的时间规则**

1. `at_sec` 必须落在锚定镜头内。
2. 旁白与任何台词之间至少留 **0.08s** 空隙；不允许重叠。
3. 旁白与另一条旁白之间至少留 **0.08s** 空隙；不允许重叠。
4. `timing_sec` 不得小于 `ceil(汉字数 / 5)`（5 字/秒，与台词语速 4.5 分开），建议再留 10–20% 余量。
5. 旁白只能有一个权威副本；`script` 与 `storyboard` 不得重复写同一段旁白。
6. 找不到满足条件的空位，输入层必须**拆分、缩短或改锚点**；不要依赖实现层移动超过 `max_shift_sec`。
7. 所有时间写绝对秒，保留 0.01s 精度；帧对齐由下游处理。

**旁白写作与排期规则**（排期流程见用户侧修改说明 §2.5）

1. 先排台词，再把旁白放进空位，不要先写旁白再让台词挤进去。
2. 4 秒旁白按中文约 20 字控制；5 秒约 25 字。超过就拆句。
3. 旁白和台词在同一场时，两者之间必须留 ≥0.08s 空隙。
4. 旁白时长超过所在镜头时，必须显式使用 `voiceover_span`，并确认跨度内没有台词。
5. 旁白不要跨场景；确需跨场景时显式写 `allow_cross_scene=true`，并说明理由。
6. 不允许把旁白写进 `audio` 字段；`audio` 只放台词/同期声。
7. 内心独白 `kind=inner` 的 `speaker` 必须是该镜 `subjects` 或 `ref_characters` 里的角色。
8. 解释性旁白 `kind=exposition` 的 `speaker` 固定 `NARRATOR`。

## 9. 适配层契约（不属业务契约，但必须存在）

### 9.1 职责

**输入**：v10.1 业务资产（plan / script / storyboard）+ 运行时配置。
**输出**：某个具体生成引擎的内部参数。
**规则**：更换引擎时，**只重写本层**。

### 9.2 必须实现的推导（缺失即为缺陷）

| 业务输入（A/B 层） | 适配层推导出的引擎参数 |
|---|---|
| `visual_bible` 槽位 | 该引擎的风格条件（文本串 / 风格参考图 / 条件向量） |
| **`visual_bible.forbidden` + 质量基线** | **该引擎的负面条件**（若引擎支持）。**必须覆盖 `forbidden` 全部词条**；不支持负面条件的引擎须以等效排除机制实现（v10.1） |
| `framing.subjects[].pos` + `height_level` + `depth` + `overlap_order` | 该引擎的空间控制参数（分区掩码 / 参考图分配 / 图层位置） |
| `pos` + `composition` + 其余事实字段 | 精确归一化坐标（若引擎需要）。**优先用结构化字段，NL 解析仅作兜底** |
| `occludes` 直接遮挡 | 完整遮挡链（递归展开） |
| `scene_type` + `requirements.quality_tier` | 具体档位参数（模型大小 / 步数 / 参考图数量 / 预算） |
| `requirements.interpolation` / `dubbing` | 插帧 / 配音链路的启用与档位 |
| `output.aspects` + `resolution_policy` + `min_resolution` | 该引擎友好的像素尺寸桶（**不得低于 `min_resolution`**） |
| `derivation` 策略 | 对应的生成/派生任务 + `derived_from` 记录 |
| `requirements` 全部键 | 实现，或**明确报"不支持"**（§4.5）；并输出**生效链**（§4.3） |

### 9.3 反模式（明令禁止）

1. ❌ 适配层把引擎专属参数**写回 A 层字段**。
2. ❌ A 层出现引擎专属参数，并被当作可选"逃生舱"长期依赖。
3. ❌ 声明了某能力，适配层悄悄降级执行且不报错。
4. ❌ 上游为了迁就当前引擎，被迫手写坐标、像素、模型名。
5. ❌ 把引擎负面表写进业务资产（v10.1 新增，`negative_prompt` 即此形态）。

> §9.3.3 正是 v9 `img2img_multi` 事故的形态。契约层无法靠"写得更好"防止它，必须靠机制：A/B 层 `extra="forbid"` + §4.5 的"不支持必须报错"启动自检 + §4.3 的生效链审计。

### 9.4 C 层与生效链的生命周期（v10.1 新增）

> **`hints` 与生效链均为瞬时派生，不持久化。**

- `hints` **不进入资产库**：渲染时由适配层生成，用后即弃。
- 若因缓存等原因落盘，**换引擎时必须强制清空重推**。
- 生效链写入**运行时报告**（独立于资产），用于审计与回归。
- 理由：旧引擎参数一旦持久化，换引擎后会**污染新引擎**，且违背 C 层"无一兼容承诺"的定位。

### 9.5 `derived_from` 的存放（v10.1 明确）

- **存放位置**：派生画幅的**资产记录**（资产库侧），格式 `{"aspect":"9:16","source_aspect":"16:9","source_asset_id":"..."}`。
- **不写入 storyboard 资产文件**（storyboard 是业务输入，不含运行时产物引用）。
- storyboard 侧仅通过 `derivation` 声明**策略**；实际派生关系由资产库维护。
- §10.1 的 `derived_from` block 校验针对**资产库记录**，在校验门中作为独立检查项执行。

### 9.6 旁白与转场的下游消费清单（v10.2 新增；v10.3 更新旁白口径）

> 输入层只负责把旁白/转场写成 A 层事实；**是否出声、是否加转场特效属于适配层职责**。
> 下游若只同步 schema 而不同步执行链，会出现“字段声明了、成片里没有”的静默降级，违反 §9.3.3。

**必须同步的读取侧**

1. 若适配层自带一份 v10.3 schema / dataclass / 解析器，必须补齐：
   `Scene.narration`（v10.3 起恒为空数组）、`Scene.transition_in`、`Shot.narration`（含 §8.4 锚点字段）、`Shot.transition_in`。
   否则 A 层 `extra="forbid"` 会把新字段判为 block；若解析器是 `extra="ignore"`，
   则会静默吞掉，同样不可接受。
2. 复用本包 `manju.schemas` 的适配层无需改模型，但要确认运行时用的是**新版本**
   （`SCHEMA_VERSION == "v10.3"`），并重新跑一遍 `gate` / `drama`。
3. **旁白只认 shot 级**：门禁、TTS、字幕、混音都以 `storyboard.shots[].narration` 为唯一
   权威；`script.scenes[].narration` 恒为空，读到非空即 v10.2 遗留，须以 shot 级为准并报警。
4. 所有新增字段均为可选：旧产物（没有这些字段）继续按空列表 / `null` 读取，
   `schema_version` 仍可写 `v10.1` / `v10.2`，不需要迁移脚本。

**字幕 / TTS / 混音**

- `shot.audio` 仍然**只放台词**（`同期` / `画外`），不要往里拼旁白，否则外部
  storyboard 的台词解析器会把旁白当口型台词。
- 字幕轨需追加 `shot.narration[]`，按 `at_sec`（全集绝对时间）排入，`timing_sec`
  为建议时长；`exposition` 与 `inner` 可用不同字幕样式区分。
- TTS 需为 `exposition` 配置叙述者音色，为 `inner` 使用角色音色（可更干、更近）；
  两者都**不得**触发 LatentSync / 口型，不设置 `subjects[].speaking=true`。
- 混音时旁白是叠轨：按 `at_sec` 放入即可，不占镜头时长；与台词重叠时应压低
  台词/原声（ducking），避免口播糊在一起。
- **排期器（v10.3 新增）**：gate 与 dub 共用同一“最近可行空位”排期器——
  先排台词、再按 `max_shift_sec` 在空位内放置旁白；找不到空位时输出精确冲突信息
  （哪个镜头 / 哪句台词 / 缺口几秒），并禁止“只向后顺延”的贪心（0.1s 级联成十几秒）。

**转场**

- `match_cut` / `action_bridge` / `sound_bridge` 是**剪辑理由**，默认不产生视觉特效；
  适配层不要擅自加淡入淡出。
- `fade` / `dissolve` / `time_jump` 才适合映射为场景边界的 xfade / dip-to-black；
  引擎不支持时保持硬切并记录“未实现转场特效”，不要静默改语义。
- `transition_in` 只出现在场次第一镜；读取时以该镜为准，不要逐镜重复应用。

## 10. 校验规则分级

### 10.1 block（阻断，机械可判定）

**引用完整性**
- `char_id` 不在 `plan.characters`
- `wardrobe_state` 的 `state_id` 不在该角色状态库
- **`subjects[].wardrobe_state` 与 script 同场 `wardrobe_state` 不一致**（v10.1 新增）
- `ref_characters` 未被 `subjects` 全覆盖
- **`ref_characters` 含画面外角色**（该角色在 subjects 中未标 `offscreen=true`、且 prompt_en 无任何画面指代；v10.3 补充）
  > 语义（§8 示例注释）：`ref_characters` 只列**画面内**角色——含局部/道具/肢体代指与全景极小在场；有声音/被提及但不在画面的画外角色（对话对象、画外音主体）必须走 `subjects[].offscreen=true`，不得并入 ref。
  > 过渡：v10.3 前产物存在把画外对话对象并入 ref 的写法，重生成时按本口径收敛（warn 级，不回溯改造旧产物）。
- `occludes` 存在循环（A 遮挡 B、B 遮挡 A）
- `script` 引用了 plan 中不存在的角色（禁止动态新增）
- **`subjects[].char` 与 `ref_characters` 必须全部 ∈ 本镜所属场景的 `chars_on_screen`**
  > 后果比"出图漏人"更重：`cast_separation` 的同框图**正是据 `chars_on_screen` 构建**，storyboard 越界加人会让这一对角色逃过区分度校验——等于绕过防串脸的第一道防线。
- **`character_flags` 中 `disguise:<char_id>` 的目标必须存在于 `plan.characters`**
- **`overlap_order` 与 `occludes` 矛盾**
- **`lines[].speaker` 必须 ∈ 本场 `chars_on_screen`**（v10.1 补充）
  > 依据同 §7 对 `chars_on_screen` 的定义：它是"本场实际出场"的唯一表述。有台词却不在名单里 = 名单漏列，出图会漏人（与"在场没台词也要列出"是同一条规则的两面）。

**时间轴**（v10.1 加容差；v10.3 旁白锚点并入）
- `ceil(len(text) / cps) > timing_sec`
- `at_sec` 越界或同镜内重叠
- 镜头时长之和 ≠ 场景时长；场景之和 ≠ 单集时长 —— **容差 ±0.2s，超出容差才 block**（浮点累加与四舍五入不应卡死整集）
- **旁白 `timing_sec` 小于 `ceil(len(text) / 5)`**（5 字/秒，与台词语速分开）
- **旁白 `at_sec` 不落在锚定镜头区间内**（v10.3：按 `shot_id` 找锚镜，缺省按承载镜）
- **`within_shot` 旁白越出锚镜**（`at_sec + timing_sec > shot.end_sec − 0.08`）
- **`voiceover_span` 未声明 `allow_span_shots`，或跨度超过 `allow_span_shots`**
- **`allow_cross_scene=false` 时旁白跨越了场景边界**
- **旁白与台词 / 旁白与旁白重叠，或空隙 < 0.08s**
- **旁白没有锚点字段**（`anchor_mode` / `shot_id` / `at_sec` / `timing_sec` 任一缺失；v10.3 起写旁白即要求完整锚点）
- **`shot_id` 指向不存在的镜头**

**旁白与转场（v10.2 叙事增强；v10.3 收口到 shot 级）**
- `narration[].kind` 不是 `exposition` / `inner`
- `exposition` 的 `speaker` 不是 `NARRATOR`；`inner` 的 `speaker` 不是本场/本镜角色
- **`script.scenes[].narration` 非空**（v10.3 起必须留空；读旧产物时以 shot 级为准并 warn）
- 旁白叠在台词拍上（**剧本生成阶段** block；编译后的契约不保留 `beat`，
  下游按 `at_sec` 与台词时间轴消费，不再做拍级判定）
- `narration_mode="off"` 时仍写入旁白；或 `narration_mode="on"` 时本集没有任何旁白
- 本集 `exposition` 条数超过 `story.narration_max_exposition`，或 `inner` 条数超过 `story.narration_max_inner`
- 第 2 场起缺少 `transition_in`（`transition_mode="auto"` / `"on"` 时 block；`"off"` 时降为 warn）
- bridge 类转场（`match_cut` / `sound_bridge` / `action_bridge`）缺少 `anchor`（同上，按模式升级）
- 场次首镜的 `cut_reason` 与 `transition_in.type` 不兼容（编译器会确定性修正并校验）

**跨集连续性**（v10.1 新增）
- **`ep_N.continuity_ledger` 末态 ≠ `ep_{N+1}` 初始态**（服装态 / 伤势 / 持有道具）→ block
  > 漏记一集会连锁污染后续所有集，这是百集场景的硬伤，必须机械拦截。
- 该校验**只看时间线内变化**；含 `flashback` / `vision` 标记的场次不计入（§7.3）

**画风**
- `visual_bible` 槽位值命中 `forbidden`（含复合词与中文词）
- `storyboard.style_suffix` 非空
- `desc_en` 命中场景/背景禁词

**契约与解耦**
- A/B 层出现未知字段
- **A/B 层字段"值"命中命名禁令（含自由文本字段值）**（v10.1 收紧）
- `requirements` 取值非法
- **声明的能力未被适配层实现且未报"不支持"**
- **声明—执行不一致**（声明某派生策略却独立重生成；声明 `locked` 却按更低档执行）
- **`derived_from` 缺失**（§6.4 规则 2；针对资产库记录）
- 适配层产出尺寸低于 `output.min_resolution`

**对白与口型（v10.2 新增/明确）**
- 画内台词说话人不在本镜 `subjects` / `ref_characters`
- 有画内台词却未声明 `requirements.dubbing = "lipsync"`
- `subjects[]` 已声明 `speaking`，但画内说话人中**没有任何一个** `speaking: true`
  （`null` / 缺省视为未声明，不检查）
- 台词按 `speech_cps` 估长，在 `atempo ≤ 1.5` 压缩后仍装不下本镜可用帧数

**结构**
- `schema_version` 缺失或大版本不匹配
- **`framing` 缺少任一「该镜实际启用画幅」的构图**（v10.1：基准按 shot 级 `aspect_overrides` 判定，非 plan 全局）
- 同框 ≥2 人的镜头 `multi_subject_strategy` 未显式填写（§4.4）

### 10.2 warn（告警，不阻断）

- `visual_bible` 自由槽位出现非摄影术语
- `desc_cn` 出现场景词；`desc_cn` 与 `desc_en` 外貌要素不一致
- `color_signature` 色相距离过近（仅辅助，**不替代人工维度判定**）
- **`framing[<画幅>].subjects[].char` ⊄ 本场 `chars_on_screen`**（非 `offscreen` 者）——走的是与 `subjects` 越界同一个绕过 `cast_separation` 的口子，但 framing 是"画面内站位"而非出场名单，可能有正当例外，故先只告警
- `cast_separation` 存在同框机会的角色对差异 < 3 维
- shot 级 `aspect_overrides` 使某画幅一致性等级低于 plan 默认（§6.4 规则 5）
- `prompt` 与 `segments[].text` 语义冲突（以 `prompt` 为准）
- **`prompt` 与结构化字段（`framing` / `subjects` / `motion` / `ref_characters`）冲突**（以**结构化字段**为准，§8.2）
- **`prompt` 出现 ≥2 种景别词**（提示词在描述两套景别 = 要求镜内切，§8.2）
- **`prompt` 景别与 `framing` 只差 1 档**（中景 ↔ 中近景；同机位松紧，通常可忍，§8.2）
- **台词正常语速装不下、但 `atempo ≤ 1.5` 压缩后可装下**（配音会被动加速，§7.1）
- 同镜多个画内说话人（是否可接受由你的口型引擎能力决定；单参考图/单口型引擎通常在 config 里配 `story.max_lines_per_shot: 1`）
- 声明 `lipsync` 但本镜没有画内台词
- `plan_version` 未随 `identity_lock` 变更而升级
- 同一拍叠了多条旁白（**剧本生成阶段**；编译后的契约改按 `at_sec` 检查旁白之间的重叠）
- 旁白只是在复述可见动作，而不是补画面外的前情/规则/内心
- 本集旁白合计时长超过目标时长的 18%（对白稀疏集为 30%）
- 对白稀疏集没有任何旁白（建议至少 1 条，仅为软提示）
- `time_jump` / `fade` / `dissolve` 未写 `anchor`（建议补时间/空间落点）
- 第 1 场仍写 `transition_in` 且 `transition_mode="off"`（可留空，除非承接上集）
- C 层 `hints` 出现未知键

### 10.3 info（仅记录，不告警）

- `advisory_episodes` 与实际集数不符（v10.1 由 warn 降为 info）
  > 闪回、剧集重排、时间回溯天然导致不匹配，长期 warn 会淹没真正的告警。

> **流程要求**：warn 必须进入**每周回归报告**并量化跟踪，否则 warn 会累积成"已知但不管"的债务。

## 11. v9 → v10.2 迁移（全量字段清单）

**原则**：读取兼容 v9，产出必须 v10.2，不做永久双读。

> 下表沿用 v10.1 的迁移规则；v10.2 只新增可选字段，不改变 v9 → v10.1 的映射。

### 11.4 `x → pos` 反推的失败场景与兜底

**必然失败或不可靠的场景**
- 多个角色 `x` 值接近（0.48 与 0.52）→ 无法确定归属 `left` 还是 `right`；
- 非水平构图（居中堆叠、纵向列队、环绕）→ 1D `x` 反推不出语义 `pos`；
- 反向 / 镜像构图 → 反推出错；
- `x` 缺失或为 `null`。

**兜底（三级）**
1. 能唯一映射 → 自动反推，标记 `derived` 来源；
2. 不能唯一映射 → **半自动**：用 `composition` 原文 + 上下文生成**候选 `pos`**，交编剧确认（而非纯人工重写）；
3. 仍无法确定 → **⑤ 报错**，要求人工补齐。

### 11.5 compat 防温床原则

> **compat 模式下，任何无法映射到 v10.1 的 v9 字段，必须产生显式告警日志并计入迁移报告。不允许静默忽略。**

迁移报告作为回归基线提交，人工确认后才算迁移完成。

### 11.7 v10.2 → v10.3 迁移（旁白收口 + 锚点补齐）

**必改项（v10.3 语义收紧，gate 行为级拦截）**

1. **旁白去重**：同一段旁白只留 `storyboard.shots[].narration`；把
   `script.scenes[].narration` 全部清空。
2. **每条 shot 旁白补锚点**：`anchor_mode` / `shot_id` / `at_sec` / `timing_sec` /
   `allow_span_shots` / `allow_cross_scene` / `max_shift_sec`（默认 3.0）。
   判断规则：旁白完整落在锚镜内 → `within_shot`（`at+timing ≤ end−0.08`）；
   否则 → `voiceover_span` + `allow_span_shots`（按需跨镜数，默认不跨场）。
3. **校验空隙**：与台词、与其他旁白之间留 ≥0.08s；不足则**拆分 / 缩短 / 改锚点**，
   不依赖实现层移动超过 `max_shift_sec`。

**可选（建议）**

- 目标集长向 90s 对齐（§7.1 结构表）；180s 的老产物可保持原时长先交付，
  后续按剧情重切时再向 90s 收敛。
- 时长余量：`timing_sec` 在 `ceil(汉字数/5)` 基础上留 10–20% 余量。

**兼容性**：schema 层新字段全部可选，旧产物（v10.1 / v10.2）原样可解析；
门禁对"有旁白无锚点 / 时间冲突"给 block，属行为级向前收紧，需在迁移报告里显式确认。

## 12. v10.1 / v10.2 / v10.3 明确不做

| 不做的项 | 理由 |
|---|---|
| `characters` 支持 `$ref` 外部文件引用 | 角色数量级在数十，单文件不构成膨胀；引入后新增解析顺序、循环引用、跨文件校验三类复杂度。**若单文件超 ~1MB 再议** |
| 自由槽位白名单硬报错 | 白名单无法穷尽合法术语，硬报错会误伤；改 warn + 回归报告跟踪 |
| 每集一份 plan | 直接破坏跨集一致性，明确禁止 |
| 契约内保留任何引擎专属"逃生舱"为必填 | 逃生舱一旦必填，就变成新的耦合点 |
| 强制外部度量器（人脸相似度打分）作为契约要求 | 属实现层。契约只要求"生效链可审计"（§4.3） |
| `background_fidelity` / `scene_reuse` / `expression_range` 能力键 | 已被 `temporal_stability` 覆盖，或属资产缓存（非业务契约） |
| A 层字段熵 / 漂移检测 | 无可执行判据，押后 |
