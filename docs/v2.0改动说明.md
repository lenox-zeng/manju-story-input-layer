# v2.0 改动说明

## 为什么单独开 v2.0

v1.2 已经验证了“情节原子 → 戏剧单元分集 → must_show → 剧本/分镜对账”的方向，
但后续改动会同时碰配置、运行目录、Studio 与质量工具，继续在 v1.2 上改容易把
“正在维护的旧版”和“正在试验的新版”混在一起。因此：

- **v1.2 冻结为只读基线**，只修它自身的缺陷；
- **v2.0 成为活跃项目区**，新功能、连贯性迭代、审计工具都在这里做；
- 两边不共享代码目录、`config.json`、`state/input/output/logs` 或虚拟环境。

## 这一版做了什么

### 1. 独立运行区

- 新目录 `manju-story-input-clean_v2.0/`，从 v1.2 复制**干净代码**（历史工作区含两本样书；纯净包不附）。
- 没有复制 v1.2 的 `state/` 成品、`output/`、`logs/`、`artifacts/` 与历史调研报告。
- v2.0 使用自己的 `config.json`、`state/`、`input/`、`output/`、`logs/`。
- Studio 默认端口改为 **8092**，v1.2 的 8091 可以同时开。

### 2. 配置

`config.json` 补上情节模式相关默认键：

```text
llm.story_plot_mode = true
llm.story_plot_atom_chars = 2400
llm.story_plot_atom_excerpt = 900
llm.story_plot_max_atoms = 180
llm.story_plot_total_chars = 100000
llm.story_plot_prefix_chars_per_episode = 5000
llm.story_plot_episode_batch = 3
llm.story_chapters_per_episode = 0
llm.story_source_chars = 30000
llm.story_volume_chapters = 5
llm.story_fallback_chunk = 20000
llm.story_fallback_overlap = 500
llm.story_max_volumes = 60
llm.story_episode_batch = 10
llm.story_gate_attempts = 3

story.narration_mode = auto
story.narration_max_exposition = 2
story.narration_max_inner = 3

```

`config.json` 已在 `.gitignore` 中。API Key 从环境变量读取
（`MANJU_LLM_API_KEY` > `DEEPSEEK_API_KEY` > `OPENAI_API_KEY`），
`--doctor` 只报告来源与是否缺失，不打印内容；旧配置里的明文 `llm.api_key`
仅作兼容并会收到迁移告警。

### 3. 可复现的质量工具

- `scripts/verify_offline.py`：不调 API 的完整离线验收。
- `scripts/audit_run.py`：审计一次产物的情节/因果/道具/运镜契约。
- `scripts/pass_rate.py`：通过率测量；默认离线，`--live` 才调 API。
- `scripts/run.ps1` / `scripts/studio.ps1`：把 `MANJU_ROOT` 固定到 v2.0。

### 4. 文档与 git

- `VERSION` / `MAINTENANCE.md` / `CHANGELOG.md`。
- v1.2 源文件 SHA256 基线仅保留在原工作区；纯净包不包含该清单。
- 先写 `.gitignore` 再 `git init`，确保配置与 API Key 不进入索引。

## 继承自 v1.2 的连贯性修复

v2.0 的代码基线已经包含 v1.2 的以下改动，不是重新发明：

- 按情节原子/戏剧单元分集，不再固定 9000 字或 2 章一集；
- 每集 2–6 条 `must_show`、0–3 件 `key_props`；
- 场间 `causal_from`，禁止无因果跳场；
- 关键道具必须 `insert` + `emphasis=key_prop` + `visual_focus`；
- 分镜对 `key_prop` 强制 close/extreme-close + 非静态机位；
- `highlight/climax` 强制非静态机位；
- `cut_plan` 把 `emphasis/visual_focus` 透传给视觉提示词；
- `--to-episode N` 只读前 N×5000 字，前缀截断对齐句末/换行；
- 剧本节奏规则 19：must_show 至少 2 拍，禁止一条一拍照打卡；
- 开场钩子也强制一次运镜；
- 恢复指纹含规则修订号，旧缓存不能静默复用。

## 没有做什么

- 没有提升契约大版本（仍为 v10.2）；2026-10-27 只在 v10.2 内增补可选
  `narration` / `transition_in` 字段，旧产物按空值读取，无需迁移。
- 没有做 live 端到端生成；没有把”≥90% 通过率”写成已达成。
- 没有复制 v1.2 的成品；旧产物需要手动迁移或重跑。
- 没有把渲染/ComfyUI 执行层纳入本包；但提供了下游实现层所需的接口说明
  `docs/ComfyUI对接指南.md`（只规定如何消费契约，不含渲染代码）。

## 2026-10-30：分镜时长计算 + 阶段化子分镜（segments）

**背景**：EP01 35 镜的 `duration_sec` 只有 6 个档位（2.36–3.2s），
实现层按统一 3 秒渲染，SH03 这类”丢盘子→砸进水盆→转身扑地板”的多动作镜
必然放不下。调研确认无任何引擎用统一档位（万相官方甜区 4–6s/镜；
LTX 按 `8n+1` 帧数），且行业标配”一段一动作 + 阶段化子分镜”。

**落地内容（全部向后兼容，新字段可选）**：

1. **时长规则**（三值取大 + 对齐引擎档位）：
   `单镜时长 ≥ max(景别下限, 动作节拍数×action_seconds_per_beat, 台词秒)`
   再向上对齐 `duration_tiers`；每镜输出 `duration_basis` 中文算账记录，
   只记录不改写（保住”镜和=场和”）。
   **配套修正**：单镜上限从默认 3.2s 放宽到 6.0s（引擎档案
   comfyui=4.0 / seedance=8.0 / jimeng=6.0）——3.2s 正是”统一 3 秒放不下”
   的根因之一；剧本拍数下限的平均基准从 2.6s/镜放宽到 3.5s/镜，
   避免把每镜压成碎镜。
2. **阶段化 segments**：`segments[] = {text, duration_sec, phase,
   beat, time_range, camera_phase, state_in/state_out, keyframe,
   frame_hint, source}`，一段一个主动作，段区间连续不重叠、段和=整镜。
   **确定性兜底（2026-10-31 补，2026-11-02 修复）**：EP01 实测分镜层
   LLM 未产出 segments（68 镜 0 段），compile 层新增 `_fallback_segments`：
   对动作数>1 的镜按动作数均摊拆 2–3 段，段和=整镜、区间连续、末段
   `keyframe=true` + `frame_hint="last"`、段级 `state_out→state_in` 承接；
   段标 `source="fallback"`。
   **2026-11-02 质量修复**：旧兜底把整镜 prompt 开头 80 字符整段复制进
   每段（段间 100% 重复、剧情动作丢失、信息保留 ~15%）。新实现按动作
   从句语义重组：每段=基础定位（仅 start 段）/主体指代 + 本段分配到的
   全部动作从句，动作不丢失、段间独立；新增质量门
   `scripts/check_prompt_quality.py`（重复/截断/动作完整性判据）。
   实证：EP01 旧产物 369 BLOCK → 语义拆段重编译 0 BLOCK（4 WARN 为
   状态段提示）。LLM 精写段无 `source`。
3. **引擎差异走配置**（`manju/story/engines.py`，不写两套逻辑）：
   comfyui=`max_actions_per_shot=1` + `duration_tiers=[2,3,4]`
   （25fps 49/73/97 帧，LTX `8n+1`）；seedance/jimeng=`2` + 不设档位
   （任意整数秒）。
4. **校验**：`validate_segment_cuts` / `validate_board` 对 segments
   自洽（段和=整镜、区间连续）硬校验；动作数×基准 与
   `max_actions_per_shot` 超限为 **warn**（EDL/board 的 seconds 由剧本
   拍确定性推导，LLM 无法在此层改时长，硬拦无意义——超载靠分镜层
   拆段/拆镜 + 审计脚本兜底）。
5. **审计脚本** `scripts/audit_storyboard.py`：新增”动作数 vs 时长”
   （不足报”内容放不下，应加时长或拆段/拆镜”）与 segments 段和/区间
   连续/一段一动作检查。
6. **文档同步**：`docs/漫剧文本输入契约_v10.2.md` §8.3 新增时长算账与
   阶段化字段规范（字段全可选，契约版本不变）；`docs/ComfyUI对接指南.md`
   更新 storyboard 字段表、新增 §8.4 LTX 阶段化消费方式
   （`8n+1` 帧数对齐、LTXVAddGuide 中段注入、`condition_only` 景别
   冲突警示）。

**回归**：244 passed / 6 skipped（2026-10-31 追加兜底后 247 passed / 6 skipped，
再补 3 个 key_line 用例后 247/6 保持）；`check_contract_sync.py` 契约层

## 2026-10-31：集长硬区间 80-90s

**规则**：一集按剧情定时长，但总时长必须落在 **80-90s** 之间
（`--duration` 默认 90，CLI 校验拒绝区间外值，如历史遗留的 `--duration 180`）。
分集仍按戏剧单元定剧情归属，集长预算按 80-90s 推导拍数/台词/覆盖率；
超过 90s 的内容拆到下一集，不足 80s 的集人工确认是否并集或补戏。

**回归**：247 passed / 6 skipped 保持。
