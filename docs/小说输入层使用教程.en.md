# Novel Input Layer Usage Tutorial

Goal: **feed a single novel / short story**, and automatically parse, compress and split it into episodes, producing a **v10.2 render contract** (plan / script / storyboard / director) plus story reports, ready for a rendering pipeline (ComfyUI or any other engine).

```
novel.txt
  → ⓘ parse: encoding detect → cleanup (ads/URLs/formatting) → chapter table (no chapters → 20k-char chunks)
  → ⓘ compress: 5 ch/volume → volume event summary → story codex (≤30k chars skips)
  → ⓘ plot-driven split: ordered plot atoms → LLM groups dramatic units, decides episode count and 4–6 must_show events per episode (min 2) → ep_src_NNN.txt
  → ① global bible (characters/scenes/props/payoffs + series_design)
  → ② episode plans (≤3 eps per batch; must_show / key_props / causal chain)
  → ③ character identity locks cast
  → ④ scene/prop art
  → ⑤ screenplay (episode slice + prev/next synopses)
  → ⑥ 2D staging (episode slice + prev/next synopses)
  → ⑦ storyboard (scene-by-scene, carrying state_in / state_out)
  → ⑧ deterministic compile v10.2
  → input/<小说名>/external/plan.json + input/<小说名>/external/epNN/{script,director}.json + input/<小说名>/epNN/storyboard.json
  → state/report/index.html + epNN.html + report.webp
  → downstream render pipeline (full integration package, not in this repo)
```

Story layer and rendering layer are decoupled:

- The story layer only emits the structured fields defined in `manju/story/models.py`;
- The compiler `manju/story/compile.py` maps them to **v10.2** and does **not** call a model;
- Field definitions and validation rules are in `docs/漫剧文本输入契约_v10.2.md`. Render adapters, the capability registry and workflows belong to the **full integration package**, not this repo; upgrading workflows never changes the story layer or LLM prompts.

> Command note: this input-layer package ships a lean CLI, `python -m manju.story_cli` (no `novel` subcommand). The `manju.cli novel` form belongs to the full pipeline package.

> **Two frontends, one pipeline**: this is the CLI tutorial. For the local web UI see
> `docs/Studio使用教程.md`; Studio's Generate page calls the same `story_cli` and its
> Publish step reuses the same compiler + gate/drama audit, producing identical artifacts.

## 1. Prerequisites

1. Python 3.11+ with a virtual environment: `.venv\Scripts\python.exe` (Windows) or `.venv/bin/python` (Linux/macOS).
2. A text-model API configured in the `llm` section of `config.json` (`base_url / model`, **DeepSeek**, OpenAI-compatible). Provide the key via environment variable:
   ```powershell
   $env:DEEPSEEK_API_KEY = "<your key>"
   ```
   `MANJU_LLM_API_KEY` / `OPENAI_API_KEY` also work; `--llm-url` can override the endpoint.
3. No local GPU, ComfyUI or VRAM management is required: this package only emits the contract; rendering belongs to the downstream pipeline.

> Do not store a plaintext key in `config.json`. Legacy `llm.api_key` still works for compatibility, but `--doctor` warns and prompts migration. If a key has ever appeared in a terminal, log, or chat, revoke it at the provider first.

## 2. Input Parsing (no model calls)

`manju/story/ingest.py` handles encoding and chapter detection. `--dry-run` parses only — no LLM, no writes.

### 2.1 Encoding auto-detection

Tries, in order: UTF-8, UTF-8 BOM, UTF-16 (incl. BOM-less heuristic), GBK / GB18030. Binary or empty files raise a clear error.

### 2.2 Chapter detection

Recognizes line-leading titles, up to 60 chars:

- `第X章 / 回 / 节 / 卷 / 部 / 篇 / 集` (Chinese numerals, Arabic, full-width digits);
- `楔子`, `序章`, `序言`, `序幕`, `引子`, `前言`;
- `尾声`, `终章`, `后记`;
- `番外`, `番外篇`, `番外 3`;
- `Chapter N`, `Part N`, `Volume N` (Roman or Arabic, case-insensitive).

The chapter table carries: index, title, start/end offsets, type, char count. Pre-title text is grouped into a "prologue" segment.

### 2.3 Preprocessing cleanup (on by default)

This is the **first stage after receiving a novel**, running before chapter detection and episode splitting. It is pure rules, makes no LLM calls, and is idempotent.

What it does:

- Normalizes line endings (CRLF/CR → LF) and strips BOM, zero-width chars, and control chars;
- Removes `<script>/<style>`, common HTML tags, and entities left by web scraping;
- Collapses repeated spaces/tabs and removes typesetting spaces next to Chinese punctuation and between two Han characters; **headings are exempt**, so `第一章 开始` is not changed to `第一章开始`;
- Drops whole lines that are clearly short URLs/site/ads: `www.xxx.com`, `http://...`, site watermarks, "latest chapter", "add bookmark", "request votes/tips", etc.;
- Replaces separator lines (`***`, `---`, `……`, `~~~~`) with blank lines;
- Removes an inline URL inside a prose line but keeps the rest of the line.

What it does not do:

- No rewriting of prose and no automatic mojibake repair (mojibake is reported only — guessing characters is riskier than keeping them);
- Never deletes chapter headings, author names, book titles, or author notes;
- Never overwrites the source file.

Inspection:

- `--list-chapters` / `--dry-run` print the cleaned char count, content chars, CJK chars, the "raw → cleaned" char counts, removed-line counts by category, and warnings;
- When content changes, the work dir gets `cleaned.txt` and `cleanup_report.json` (removed examples + removed ratio);
- If more than 10% of content chars were removed, a warning asks you to inspect for accidental deletions;
- Disable with `--no-cleanup`.

> Char metrics: **raw** includes spaces/newlines; **content** excludes all whitespace; **CJK** counts Han characters only. Use content/CJK for episode and duration estimates, not file size.

### 2.4 No-chapter fallback

If no chapter is detected across the whole book:

- Split by `llm.story_fallback_chunk` (default 20000 chars);
- Adjacent chunks overlap by `llm.story_fallback_overlap` (default 500 chars);
- Prefer to cut at line/sentence ends rather than splitting a sentence;
- In chapter mode with no detected chapters, the CLI warns and falls back to char-based splitting.

### 2.5 Inspect the chapter table

```powershell
# encoding, total chars, chapter table only
python -m manju.story_cli input\my_story.txt --list-chapters

# parse + episode-split rehearsal (no LLM, no writes)
python -m manju.story_cli input\my_story.txt --dry-run --yes
```

Run the parser standalone:

```powershell
python -m manju.story.ingest input\my_story.txt --list-chapters
python -m manju.story.ingest input\my_story.txt --json
```

## 3. Automatic Episode Splitting

### 3.1 Default: plot-driven split

With `--episodes auto` (the default), no manual map / chapter count, and
`llm.story_plot_mode=true`, the pipeline runs in **plot mode**:

1. Split the cleaned novel into ordered "plot atoms" of ~2,400 chars (exact source offsets, no gaps or overlap);
2. The LLM reads atom excerpts and groups them into dramatic units ("goal → obstacle → turn → cost/climax → new problem"), deciding the episode count itself; for each episode it writes 4–6 (minimum 2) causally linked `must_show` events, 0–3 `key_props`, and `dramatic_question / turn / climax / hook / cliff`;
3. Code deterministically repairs atom ranges so the whole source is covered exactly once;
4. Each episode slice is written to `ep_src_NNN.txt`; later script/storyboard stages reconcile every `must_show`.

> Key point: **an atom range is source material, not a shot list**. A 90-second episode performs 4–6 (minimum 2) `must_show` events; other source events become background or are left out. The old "9,000 chars or 2 chapters crammed into 90 s" behavior is gone.

```powershell
# Preview plot atoms (no LLM call)
python -m manju.story_cli input\my_story.txt --dry-run --yes
# Full generation
python -m manju.story_cli input\my_story.txt
```

For a long novel where you only want the first N episodes, use
`--from-episode 1 --to-episode N`. The design stage reads only the first
`N × llm.story_plot_prefix_chars_per_episode` chars (default 5,000/episode),
snapped to the nearest sentence/line boundary (within about 200–400 chars),
then keeps the first N dramatic units. It does not pay tokens for the
ungenerated remainder, and the first episodes are not diluted by the whole book.

### 3.2 Chapter/char split (opt-in)

Explicit `--episodes N`, `--episode-map`, or `--chapters-per-episode` disables
plot mode and returns to chapter/char splitting (or force it with
`--no-plot-mode`). With chapters, `N = --chapters-per-episode`, else
`llm.story_chapters_per_episode` (default 0 = off):

```powershell
python -m manju.story_cli input\my_story.txt --chapters-per-episode 2
python -m manju.story_cli input\my_story.txt --chapters-per-episode 3
```

Character counts act only as a **safety valve**:

1. A group exceeding `1.5 × llm.story_chars_per_episode` (default 13,500 chars) is split by paragraph;
2. A group under `max(1000, llm.story_chars_per_episode / 3)` (default 3,000 chars) is merged into a neighbor to avoid a 200-char episode;
3. Slices remain contiguous, non-overlapping, with no missing text;
4. `--episodes N` and `--chapters-per-episode` are **mutually exclusive**: an explicit episode count uses char mode (`ceil(total_chars / story_chars_per_episode)`, still snapping to chapter boundaries);
5. `--episode-map` has the highest priority for manual chapter/offset boundaries;
6. With no detected chapters, chapter mode falls back to char mode with a warning;
7. Slices are written to `state/story/<novel_name>/ep_src_NNN.txt`.

> Note: `--episodes N` means "split the whole novel into N episodes", not "generate only N episodes".

### 3.3 Above the auto limit

`llm.story_max_auto_episodes` defaults to 12. When auto-splitting exceeds 12 episodes:

- An interactive terminal asks for confirmation;
- Non-interactive environments (CI/pipelines) must pass `--yes`, else exit code 2;
- You can also give an explicit episode count or a manual map.

### 3.4 Manual episode map

`--episode-map` accepts two JSON forms; episode numbers must be contiguous and text must not overlap:

```json
{
  "1": {"chapters": [1, 12]},
  "2": {"chapters": [13, 30]},
  "3": {"start": 120000, "end": 240000}
}
```

or an array:

```json
[
  {"ep": 1, "chapters": [1, 12]},
  {"ep": 2, "start": 120000, "end": 240000}
]
```

```powershell
python -m manju.story_cli input\my_story.txt --episode-map my_episodes.json
```

### 3.5 Range generation / resume

```powershell
# process only episodes 5–20
python -m manju.story_cli input\my_story.txt --from-episode 5 --to-episode 20

# reuse intermediates that already passed the quality gates
python -m manju.story_cli input\my_story.txt --resume
```

- Episodes outside the range are neither generated nor compiled;
- `--from-episode N` (N>1) reads `state/story/<小说名>/board_ep{N-1}.json` and uses the previous episode's `state_out` as the Nth episode's `state_in`;
- The script side links the same way: it reads `state/story/<小说名>/script_ep{N-1}.json` as the previous episode's script ending, so episode N's writing still sees the previous episode's close (cross-episode continuity does not break across a range jump);
- If the previous episode's cache is missing, it prints a WARN and starts from empty state.

## 4. Long-Novel Compression

### 4.1 Short stories

If the source ≤ `llm.story_source_chars` (default 30,000 chars), it is **not** compressed and goes straight to the global bible stage.

### 4.2 Volume summaries

Above 30,000 chars:

1. Split into volumes by `llm.story_volume_chapters` (default 5 chapters);
2. Generate an event summary per volume: who did what, result, props, spatial details, `new_entities`;
3. Merge into a continuous story codex, capped at `llm.story_source_chars` (default 30,000 chars);
4. Volume cap `llm.story_max_volumes` (default 60); beyond that only the first 60 volumes are compressed and it is **explicitly** flagged `truncated`, recording the omitted chapter ranges.

Volume summaries are cached per-volume as `state/story/<小说名>/volume_NNN.json` and reused on `--resume`.

> No silent truncation: the `truncated` flag and warnings appear in the CLI output and in the volume-summary / outline warnings; there is no separate `codex.json` file.

### 4.3 Configuration

```json
{
  "llm": {
    "story_source_chars": 30000,
    "story_chars_per_episode": 9000,
    "story_chapters_per_episode": 0,
    "story_plot_mode": true,
    "story_plot_atom_chars": 2400,
    "story_plot_atom_excerpt": 900,
    "story_plot_max_atoms": 180,
    "story_plot_total_chars": 100000,
    "story_plot_prefix_chars_per_episode": 5000,
    "story_plot_episode_batch": 3,
    "story_volume_chapters": 5,
    "story_max_volumes": 60,
    "story_fallback_chunk": 20000,
    "story_fallback_overlap": 500,
    "story_episode_batch": 10,
    "story_max_auto_episodes": 12,
    "story_gate_attempts": 3
  }
}
```

`story_gate_attempts` is the max rewrites per stage when it fails a quality gate (default 3).

## 5. Two-Level Outline and Per-Episode Source

### 5.1 Global bible + episode synopses

- **Global bible**: adaptation decisions, spine, power_rule, character/scene/prop tables, payoff points; no episode synopses;
- **Episode synopses**: generated in batches, at most `llm.story_episode_batch` (default 10) per batch;
- Each batch is cached as `state/story/<小说名>/episodes_batch_NNN.json`; `--resume` only re-runs batches that failed gates.

### 5.2 Give each episode only the source it needs

Screenplay / staging / storyboard no longer use `source[:4000]`:

| Stage | Input |
|---|---|
| Screenplay | current episode slice (≤6000 chars) + prev/next synopses + global bible |
| Staging | current screenplay + current scene art + current slice (≤6000 chars) |
| Storyboard | current screenplay + current scene/staging + current slice (≤5000 chars) |

When a slice is too long, keep head 60% / tail 40% and explicitly mark the omitted middle — never pretend it is the full text.

## 6. Common Options

```powershell
# auto-split (default)
python -m manju.story_cli input\my_story.txt --yes

# explicit episodes, 120 s each, vertical
python -m manju.story_cli input\my_story.txt --episodes 3 --duration 120 --ratio 9:16

# adjust per-episode char budget
python -m manju.story_cli input\my_story.txt --chars-per-episode 7000 --yes

# manual episode map
python -m manju.story_cli input\my_story.txt --episode-map my_episodes.json

# parse/split only — no LLM, no writes
python -m manju.story_cli input\my_story.txt --dry-run --yes

# chapter table only
python -m manju.story_cli input\my_story.txt --list-chapters

# outline only first (P0 blocking point), continue after review
python -m manju.story_cli input\my_story.txt --review-outline
# edit state/story/<小说名>/outline.json, approve, continue
python -m manju.story_cli input\my_story.txt --approve outline --resume

# outline/characters/art only, confirm prompts by hand
python -m manju.story_cli input\my_story.txt --review

# continue after confirmation (reuse gate-passed intermediates)
python -m manju.story_cli input\my_story.txt --review --resume

# on gate failure: write a failure package, then wait interactively for a fix
python -m manju.story_cli input\my_story.txt --on-gate-fail ask

# escalate soft gates to errors (default: warning only)
python -m manju.story_cli input\my_story.txt --strict

# overwrite existing input artifacts
python -m manju.story_cli input\my_story.txt --force

# Only clear the current novel's temp work dir (.work_<novel_name>); a committed product is kept
python -m manju.story_cli input\my_story.txt --clean --yes

# disable reports (generated by default)
python -m manju.story_cli input\my_story.txt --no-report
```

> `--run` / `--plates` (rendering-side, e.g. `--run anchors|full`, `--plates`) belong to the full integration package and require ComfyUI — not part of this repo.

## 7. Quality-Gate Tiers

Every stage runs deterministic checks on completion; failures are fed back to the model for rewriting.

### 7.1 Hard gates (always error)

**IDs & references**
- Character / scene / prop ID loops are closed — no references to non-existent objects;
- Screenplay, staging and storyboard must be consistent with upstream scenes/characters.

**Duration**
- Single shot defaults to 1–3.2 s (`story.min_shot_seconds` / `story.max_shot_seconds`);
- Per-scene cut sum = screenplay scene duration (±0.3 s);
- Episode total = target (±15%).

**Dialogue**
- Dialogue is on-screen only; speaker must be among the scene's characters;
- Necessary context/rules/time-jumps and character inner voice go into structured `scene.narration` (`exposition` / `inner`), overlaid on action beats with no lip-sync; narration must not restate visible action;
- From scene 2 onward, `transition_in` must be justified (match_cut / sound_bridge / action_bridge / time_jump / fade / dissolve); bridge types require a shared anchor to avoid unmotivated hard cuts;
- A single line ≤18 Han characters by default (`story.max_line_chars`, also used by the downstream drama audit);
- Line duration must not exceed its shot.

> Narration and transitions are controlled by `story.narration_mode` /
> `story.transition_mode` (default `auto`). `narration_mode="off"` means narration
> is **not allowed** (writing it blocks); `transition_mode="off"` disables the
> "scene 2+ must declare a transition" requirement (missing becomes a warning),
> while any transition actually written is still structurally validated. Full
> defaults are in the "Engine capabilities" table in `README.en.md`.

**Frame**
- Frontal faces per framing are unlimited by default; when `story.max_faces_per_shot` is set, that limit applies and `allow_multi_face` can explicitly mark a back/silhouette-only crowd;
- `prompt_en` must be non-empty; prompt language for cast, art and first-frame storyboard fields is controlled by `story.prompt_language` (default `en`; `zh`/`any` relax it), with no camera-motion or art-style words;
- Every shot must provide `framing` for every enabled aspect (`shot_size` / `subjects` / composition); a missing enabled aspect is a hard-gate block;
- `subjects` must cover `characters`.

**Plot (plot mode)**
- Every `must_show` event must land in at least one scene (claimed verbatim by `major_event`, or actually performed in scene text);
- Scene 2 onward needs `causal_from` that visibly follows from the previous scene's result;
- Every `key_prop` must appear on screen and get an `insert` beat with `emphasis=key_prop` and `visual_focus=<prop>`;
- Every emphasis beat needs `visual_focus`; storyboard forces key-prop beats to close/extreme-close with non-static camera.

**Structure & hook**
- The last scene must be a "closing hook";
- `hook_beat` must fall within the first 3 beats;
- Storyboard beats must cover continuously without gaps.

### 7.2 Soft gates (warning by default; `--strict` escalates to error)

- 5–8 scenes per 90-second episode (too many scenes become one jump-cut each);
- 6–12 dialogue lines; low-dialogue auto mode drops to 2–6 lines / ≤160 chars and raises reaction/insert coverage;
- A "decision" within 20 s;
- "setback/cost" within 15–60 s with non-empty `cost`;
- At least 1 payoff point in any 3 consecutive episodes.

### 7.3 After compiling

- The compiler normalizes total storyboard duration to the episode target: spreads the difference without breaking line durations, keeps each shot within the configured duration range, and ensures downstream `scene_sum` / `episode_sum` (±0.2 s) pass;
- It auto-runs the strict `manju.gate` and `manju.drama` audits; any block reports an error and returns a non-zero exit code.

## 8. Continuity

Every cut must declare `state_out`:

```json
{
  "where":    {"C1": "north"},
  "facing":   {"C1": "south"},
  "posture":  {"C1": "standing"},
  "wardrobe": {"C1": "C1-default"},
  "props":    {"P1": "C1"},
  "injuries": {"C1": "left arm bandaged"}
}
```

`where` / `facing` use a controlled direction vocabulary; the other fields are free text.

Deterministic checks:

- Same-scene sequential generation: `state_in` = previous scene's end state, `previous_cuts` = the two most recent shots;
- Position jumps, facing/posture flips, wardrobe regressions, prop transfers/disappearances, injury regressions → error;
- Adjacent shots: axis / 180°, broken eyelines, shot-size jumps;
- After the full episode storyboard is generated, an audit runs; cross-episode `state_out` → next episode's `state_in`;
- Range generation inherits the end state from the previous episode cache (see §3.4).

### 8.1 Shot prompts and character identity (input-layer boundary)

The input layer does not choose the implementation layer's identity-consistency technique.
`prompt_en` always contains performance only: the action moment, pose, expression, gaze,
position, scene, and lighting. It does **not** contain names, face, build, hair, fixed outfit,
or cast-sheet pose. This avoids token waste and prevents the reference sheet's pose/background
from leaking into every shot.

Identity is emitted as structured data:

- `ref_characters`, `subjects[].expression`, and `wardrobe_state` in the storyboard;
- the full `identity_prompt` and short `identity_anchor` in
  `input/<novel>/story_assets.json`.

The implementation layer decides how to use it:

| Implementation technique | Approach |
|---|---|
| IPAdapter / PuLID / InstantID / character LoRA / face swap | Use reference, angle, and expression images; keep `prompt_en` lean |
| Pure text-to-video (no references) | Append `identity_prompt` from `story_assets.json` in the render layer |
| Multi-reference (6 angles + 7 expressions) | Select views by shot semantics; prompts carry performance only |

The input layer no longer has `story.prompt_identity_mode`; an old config key is ignored.
When the prompt policy changes, `--resume` rebuilds only prompt caches
(`shots_*` / `board_*_scene*`), not the bible/outline/script.

## 9. Story-Layer Reports

After a successful compile, reports are generated by default:

```
state/report/
├── index.html      overview: KPI, duration rhythm band, season folding, episode cards, character cards, presence matrix, scene/prop cards, gates
├── ep01.html       per-episode storyboard cards: first frame, dialogue, continuity (state_out), gates
├── ep02.html
└── report.webp     page screenshot (Pillow placeholder if no browser)
```

- Long stories fold into a season every 40 episodes via `<details>`; episodes with existing scripts still get their own `epNN.html`;
- Automatically finds a headless Chrome/Edge to screenshot and convert to WebP;
- If no browser is found, a text placeholder WebP is kept and noted in the result's `notes`;
- A report failure is only a WARN and never affects the compiled contract.

Rebuild reports standalone:

```powershell
python -m manju.report --workdir state/story --out state/report
```

## 10. Human Intervention Flow

Humans only gate the high-leverage nodes; deterministic checks still run automatically.

### 10.1 Outline approval (P0, blocking)

1. Generate the outline and stop:
   ```powershell
   python -m manju.story_cli input\my_story.txt --review-outline
   ```
2. Open `state/review/outline.html` (or `outline.md`) and review adaptation decisions, story spine, characters, scenes, props, payoff points and episode synopses.
3. Edit `state/story/<小说名>/outline.json` directly.
4. Approve and continue:
   ```powershell
   python -m manju.story_cli input\my_story.txt --approve outline --resume
   ```

Approval records the content hash of the outline. If you change `outline.json` after approval, the hash becomes invalid and you must `--review-outline` again — you cannot blank-approve.

### 10.2 Quality-gate failure escalation (P1)

Hard/soft gates are still auto-judged. On failure a failure package is written:

```
state/review/failures/latest.md
state/review/failures/<timestamp>.md
state/review/failures/<timestamp>.json
```

Default `--on-gate-fail stop` exits; `--on-gate-fail ask` waits in the terminal — press `r` to retry with `--resume`, `q` to quit. Non-interactive environments never hang and exit immediately.

### 10.3 Character / art review

1. On first run use `--review`, which only produces `outline.json / cast.json / art.json`.
2. Check:
   - Whether each `identity_lock` is distinguishable at a glance (height, hairstyle, face shape, wardrobe color);
   - Whether `wardrobe_states` cover the story changes (injury, wet, costume change);
   - Whether scene `image.prompt` is an empty scene, in English, with no character names;
   - Whether props have 3–5 reusable anchors.
3. Edit `state/story/<小说名>/*.json` directly, then:
   ```powershell
   python -m manju.story_cli input\my_story.txt --review --resume
   ```
4. If one stage keeps failing to pass after rewrites, read the failure package; fix the intermediate file, then `--resume` to re-run only the downstream stages that failed.

> `--resume` only reuses **gate-passed** caches; a failed cache regenerates automatically. A hand-edited `outline.json` takes priority over the old cache.

### 10.4 Approval files

| File | Purpose |
|---|---|
| `state/review/approvals.json` | outline/identity approval ledger (hash, time, dir) |
| `state/review/outline_required.json` | outline pending-review flag |
| `state/review/assets_required.json` | identity-image pending-review flag |
| `state/review/outline.html` / `outline.md` | outline review pages |
| `state/review/assets.html` / `assets.md` | identity-image review pages |
| `state/review/failures/latest.md` | most recent gate failure package |

`--ignore-review` explicitly skips the unapproved-outline block — for scripted debugging only, not recommended in production.

> Character identity-image approval (`--review-assets --run anchors`, `--approve assets`) and `face_qa` are rendering-side features of the full integration package.

## 11. Artifacts

| File | Purpose |
|---|---|
| `input/<小说名>/external/plan.json` | series bible: identity locks, visual bible, episodes, primary aspect |
| `input/<小说名>/external/epNN/script.json` | episode screenplay: scenes, actions, dialogue timeline, scene narration and transitions |
| `input/<小说名>/epNN/storyboard.json` | storyboard: per-shot first-frame prompt, shot size, camera, duration, dual framing, shot narration and first-shot transition |
| `input/<小说名>/external/epNN/director.json` | director layer: spine, power_rule, setup/payoff, scene dramatic fields |

## 12. Capability & Workflow Decoupling

This input-layer package **only produces contracts** and contains no rendering implementation (ComfyUI client, capability registry, adapters, or workflow JSON).

Field definitions are in `docs/漫剧文本输入契约_v10.2.md`; **how a downstream implementation reads the contract — subtitles, TTS, lip-sync, narration and transitions — is in [`docs/ComfyUI对接指南.md`](ComfyUI对接指南.md) (Chinese)**. Render adapters, the capability list and workflows belong to the **full integration package**, not this repo. When replacing a model or workflow, only the integration side changes; the story-layer models, validators and LLM prompts do not.

**Hand off only three items**: the contract, the target platform's guide, and one complete sample such as `input/<novel>/` (generated results are not included in the clean package; provide the sample separately). The contract is the single standard; a platform guide only maps it and does not duplicate it. Do not ship `manju/schemas.py` / `gate.py` / `drama.py`.

## 13. FAQ

| Symptom | Resolution |
|---|---|
| `Text model service unavailable` | Check the `llm` section of `config.json` (base_url/model), or use `--llm-url`; confirm `DEEPSEEK_API_KEY` is set; `--doctor` shows the key source |
| `plan.json already exists` | Add `--force`, or change `--out` |
| Auto-split over 12 episodes rejected | Add `--yes`, or give explicit `--episodes N` / `--episode-map` |
| Chapters not recognized well | Use `--list-chapters`; titles must be on their own line and ≤60 chars |
| Cleanup may have removed prose | Inspect `cleanup_report.json` (`examples`/`removed_ratio`); rerun with `--no-cleanup` if needed |
| Too many/few chapter-based episodes | Adjust `--chapters-per-episode`, or use explicit `--episodes N` for char mode |
| One long chapter became several episodes | Expected safety valve: a group over 1.5×`story_chars_per_episode` is split by paragraph |
| A stage keeps failing gates | Inspect the corresponding JSON in `state/story/` and the gate report; fix the file then `--resume` |
| Too many characters sharing a frame | Unlimited by default; if your engine locks one face, set `story.max_faces_per_shot` to `1` and prefer single reverse / over-shoulder / back shots |
| Character assets missing | Rendering side: build them from `story_assets.json` (`identity_prompt` / `identity_anchor`); this package does not generate images. See `docs/ComfyUI对接指南.md` |
| No report screenshot | Install Chrome/Edge, or ignore the placeholder; the HTML still opens normally |
| Narration / inner voice missing in the cut | The downstream must read `shot.narration`; reading only `shot.audio` skips it. See `docs/ComfyUI对接指南.md` |
| Scenes still hard-cut | The downstream must read `transition_in` on the first shot of each scene; bridge types add no visual effect but still need the anchor |
