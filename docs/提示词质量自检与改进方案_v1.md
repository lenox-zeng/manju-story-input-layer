## 〇、最高严重度发现：segments 阶段化层是"重复 + 剧情丢失"重灾区（用户指出的问题实证）

**整镜 prompt（prompt_en）不差，真正坏的是每镜的 segments 段文本。**

对 `input\.work_绿野仙踪\ep01\storyboard.json` 68 镜实测：

1. **65/68 镜的 segments 走的是 `_fallback_segments` 兜底**（`compile.py` L153）：
   段 text = `cut.prompt_en[:80] + （段1/3）`——**整镜 prompt 前 80 字符截断复制**，
   同一镜的 2-3 段 text 内容完全相同（只差尾注"（段1/3）"）。
2. **段文本 13-16 词，与整镜 prompt 词集重合 92-100%**：SH02 三段全是
   "medium tracking shot inside the small bare farmhouse, a girl kneeling low beside…"——
   **"scooping up a small black dog / twisting toward the door"（抱狗、转身冲向门口）
   全部丢失**；SH01 三段全是 "extreme wide shot of a vast desaturated grey prairie under
   flat leaden daylight"——**"tornado leaning down toward the house"（龙卷风压向房子）
   丢失**。整镜 prompt 84 词，段 text 只保留 13 词，**信息保留率 ~15%**。
3. **这是用户说的"重复、无效字符 + 剧情表达不完整"的最直接机制**：下游 Seedance
   尾帧串联 / LTX 中段注入吃的是 segments.text，拿到的却是同一段环境开头 × 3，
   关键剧情动作（谁→做了什么→导致什么）在阶段化层全部丢失。
4. 段内 beat（中文）有真正的动作要点（"多萝茜一把抱起托托，转身冲向门口"），
   **但没有被转写进英文段 text**——中英双份信息，英文侧只复制了开头。

**结论**：segments 是"阶段化子分镜"功能的**虚假实现**——LLM 几乎从不输出
segments（65/68 走兜底），兜底又只复制开头。修复它是本次改进的 P0。

## 一、自检结论（证据先行）

### 1.1 分镜 prompt：文本层不差，缺"摄影配方"

对 `input\.work_绿野仙踪\ep01\storyboard.json` 全部 68 镜实测：

| 指标 | 实测 |
| --- | --- |
| 单镜 prompt 长度 | min 218 / max 540 / **avg 325 字符** |
| 过短 prompt（<40 字符） | 0 |
| 运镜词残留 | 0（compile `_clean_prompt_camera` 已清洗，权威在 motion/camera） |
| 内容要素 | 主体 + 动作动词 + 情绪/表情 + 可辨识细节 + 承接（state_out 链）全齐 |

示例（SH01，extreme_wide 3.0s）：
> Extreme wide shot of a vast desaturated grey prairie under flat leaden daylight, grass bent flat in long waves, a towering black funnel of a tornado leaning down from the sky toward the tiny house …

**缺什么**（对照业界范式，见 §2）：
1. **光线方向与质量未系统化**：只有偶发描述（"flat leaden daylight"），大部分镜没有 key 光方向 / 色温 / rim / 阴影质量。业界文献直接指出：*模型不给光照说明就默认平光*——"Models default to flat, even illumination when no lighting is specified"。**这是成片"画面平、无纵深"的最主要机制**。
2. **焦段 / 景深全片锁死**：VisualBible 全片 `lens=35mm`、`depth_style=moderate DOF`，逐镜无变体。业界 shot card 是**每镜一个 knob**（对话镜 35–50mm、情绪特写 50–85mm 浅景深、环境镜 24–35mm 深景深）。
3. **构图槽位缺失**：无 headroom / rule of thirds / negative space 这类术语级指令。
4. **镜头职责**：cut_reason 有，但 prompt 里没有"本镜要证明什么"的显式职责句。

### 1.2 角色定妆 prompt：细腻，缺"跨镜固定锚点短语复用"

story_assets C1 多萝茜实测：
- `identity_prompt`（英文定妆）非常细：年龄/体型/雀斑/蓝眼/麻花辫/蓝缎带/裙装，负面词专业。
- `identity_anchor`（中文锚点）专业级："栗棕色中长发…右眉梢一道细小旧疤…跑动时辫子与裙角同时甩动"。

**缺什么**：
1. 分镜规则第 6 条只写"用外貌特征指代，不写角色姓名"——**没有强制每镜复用 identity_anchor 的固定短语切片**。跨镜一致性靠 LLM 自觉，而非 verbatim 引用。业界做法是"freeze a three-line character bible and paste it verbatim"（角色圣经逐字复用）。
2. 无表情/姿态库（pose/expression 由每镜 LLM 自由发挥，跨镜情绪表演不稳定）。
3. 无 view sheet 概念（正/侧/45° 多视角锚定，Seedance 官方推荐"角色图 1-2 张：面部特写 + 全身"）。

### 1.3 场景（背景）plate_prompt：专业，缺"光照状态注入"与"镜头建议"

- S1 plate_prompt："Empty early-1900s Kansas farmhouse interior…锈铁炉、灰漆木柜、裂纹松木桌"——材质/年代/物件全齐，负面词排除人，符合空景契约。
- `lighting` 字段有 state→prompt 映射（契约规则：每场≥1 个 lighting 状态）。
- **缺什么**：plate 本身未系统注入"光源方向 + 时间带 + 色温"（lighting 是独立字段，是否真的进生成链需 ComfyUI 侧确认）；无"该场景推荐焦段/机位"提示（如 S2 地洞适合 24mm 广角低机位）。

### 1.4 道具 prompt：本层最接近业界标准

- 尺度短语（handheld/tabletop/furniture-level）已强制；P2 活动小木门 "shown closed and then lifted" 已含状态变化；负面词含 hand/fingers。

## 二、业界优秀分镜提示词范式（调研）

### 2.1 共识结构：六层 / 五柱

多来源（Kling 官方、火山引擎 Seedance 2.0 官方、Sora 2 官方、海螺 Hailuo、Cinemagiq、OpenVideoMaker、LongStories、Domer、Neural4D、China Video AI）收敛出的同一结构：

```
[主体+细节] → [单一可观察动作（起止明确）] → [场景] → [景别+角度+运镜]
→ [焦段/景深] → [光源方向+质量+色温] → [构图] → [画风/收尾] → [画幅/时长/声音]
```

| 层 | 写什么 | 例 |
| --- | --- | --- |
| Subject | 谁/什么 + 可辨识细节（年龄、身材、服装、姿态） | 燕麦色亚麻衬衫的女人 |
| Action | **一个**几秒内能完成的动作，有起点有终点 | 握住车座抬起一次，测试弹簧 |
| Camera | 景别、角度、运镜（写提示词或运镜参数） | medium close-up, eye level, slow push-in |
| Lens & depth | 焦段当量 + 景深：24/35/50/85mm；shallow/deep DOF | 85mm, shallow DOF |
| Lighting | **光源 + 方向 + 质量 + 色温**（key/fill/rim） | soft warm key from camera left, cool rim from hallway |
| Finish | 具体画风锚点（颗粒/调色/胶片），**不是抽象词** | subtle 35mm grain, muted teal and amber grade |

### 2.2 关键共识（可直接用于改进）

1. **一镜一职责一动作**："每张分镜卡是一份小制作合同——观众得到什么信息、哪些元素必须稳定、什么可以运动、镜头以什么状态交给下一镜。"（China Video AI）与流水线"一镜一拍 + state_out 承接"完全同向，已达标。
2. **摄影参数化（shot card 每镜一个 knob）**：Domer 的 shot card 一行式——
   `SHOT 04 | MCU | eye level | 50mm | slow push in | single window key, camera left | evening interior | 3s | subject reads a letter`
   "镜头失败就换一个 knob，而不是重写整段 prompt 碰运气。"**这是当前流水线最缺的一层。**
3. **光线是写实之王**："添加一个具体光源就改变输出。写光源来源、方向、质量、色温。"（Neural4D / Hailuo）"warm key from left, deep shadows right side, soft rim separating from black background" 远好于 "moody lighting"。
4. **风格要具体，不要抽象**："cinematic / film still / 8k" 是抽象词；"35mm grain, halation, teal-and-amber grade" 是可执行词。**当前流水线规则"不要写画风词"应改为"禁抽象画风词，允许具体摄影事实词"**——VisualBible 本来就承载这些事实（35mm grain/halation/自然肤色）。
5. **角色/场景圣经逐字复用**："Freeze a three-line character bible and paste it verbatim"（Domer）；Seedance 官方素材策略：角色图 1-2 张（面部特写+全身）+ 场景图 1 张 + 运镜参考 1 段 + 音频 1 段，**不建议堆满素材**。
6. **长镜头按时间轴分镜**：Seedance 2.0 官方：复杂视频提示词用"镜头1/镜头2/镜头3"时序化——流水线的 segments 阶段化已是同思路（段 text 单动作 + 尾帧 keyframe）。
7. **运动强度与一致性权衡**：Hailuo 实测（VBench）：激进运镜 → 时序闪烁与身份漂移上升；虚拟角色镜用 slow push-in 而非 fast zoom，keep-rate 高 10–15%。流水线 drama 门限运镜已是同向。

## 四、改进方案（按优先级）

### P0：修复 segments 阶段化层——消灭"复制开头 + 剧情丢失"（最优先）

1. **分镜规则强化**（prompts.py `_board_rules` 第 22 条）：
   - segments 每段 text 必须是**该段自己的单一动作英文句**（谁→做了什么→导致什么），
     禁止复用/截断整镜 prompt 开头；整镜 prompt 与段 text 的共享前缀不得超过 20%。
   - 每段 beat（中文动作要点）必须被**翻译进该段 text**（中英同义，不是中文丢给 beat、
     英文只留环境）；段间 text 不得相同（一段一动作）。
2. **`_fallback_segments` 重写**（compile.py L125-166）：兜底不再复制 `prompt_en[:80]`，
   改为**语义拆段**：
   - 从 `cut.beat_goal / cut.motion / cut.shot` 提取动作要点，按动作数生成
     "start（起始状态+动作起点）/ mid（动作过程）/ end（动作完成+状态结果）"
     三段英文句；或按 cut 认领的剧本 beats 逐段转写（beat 是权威剧情源）。
   - 段 text 必须含动作动词（可校验）；`source` 仍标 "fallback"。
3. **质量门**（并入 P2 的 check_prompt_quality）：
   - 段 text 与整镜 prompt 词集重合率 ≤30%（目标值，可配）；
   - 同镜段间 text 两两相似度 ≤40%；
   - 段 text 含动作动词率 = 100%；段 text 非空且 ≥8 词。
   - 这三条在 EP01 现产物上会 **0/65 通过**，正好作为回归基线反例。

> **P0 实施结果（2026-11-02，已提交）**
>
> 1. **代码**：① `compile.py` `_fallback_segments` 重写为语义拆段——从整镜
>    prompt 按动作从句（`_split_action_clauses`）重组每段独立英文句：start 段=
>    基础定位+本段动作从句，mid/end 段=主体指代+本段动作从句；动作数>段数时
>    按分配数落段（**动作从句不丢失**，修复了"4 动作 3 段丢 1 动作"的缺口）；
>    段间 Jaccard 相似度 ≤0.40（旧实现 1.00）。② `prompts.py` `_board_rules`
>    第 22 条强化：禁止段 text 复制整镜 prompt 开头、禁止同镜段间相同。
>    ③ 质量门 `scripts/check_prompt_quality.py`。
> 2. **质量门判据（实现值与方案目标值的差异）**：`seg.dup`（段间 Jaccard
>    >0.60 block / >0.40 warn）与 `seg.prompt_head_copy`（非首段以整镜 prompt
>    前 15 词为前缀 block）按方案目标落地；`≥8 词` 阈值落地为 `<4 词 warn`
>    （不 block）——EP01 实测真实状态表情段（"The figure, chin trembling."）
>    词少但语义完整，硬长度判据会误伤，故长度只作提示、block 聚焦用户判据
>    的"重复/截断/剧情丢失"。
> 3. **实证**：EP01 旧产物质量门 **369 BLOCK**（全量拦截，反例基线成立）；
>    同一批真实镜头经新 `_fallback_segments` 语义拆段重编译 → **0 BLOCK /
>     4 WARN（PASS）**；新增 4 条单测（语义拆段、动作不丢失、质量门正反例）
>    全通过，全量回归 250+ passed。
> 4. **文档**：ComfyUI 对接指南 `segments` 字段说明、v2.0 改动说明兜底章节
>    已同步为语义拆段描述。
>

> 1. **P0.5 摄影配方**：① `prompts.py` `_board_rules` 新增第 23 条【摄影配方·

### P0.5：分镜层加"摄影配方"（camera_recipe）——解决画面"平"的最大根因

在每镜 `framing` 内（或并列）新增结构化槽位，由分镜 LLM 逐镜填写，**摄影事实不违反画风唯一来源**（VisualBible 管画风，recipe 管逐镜摄影）：

```json
"camera_recipe": {
  "lens_mm": "50mm",            // 枚举：24/35/50/85，对话镜 35-50、特写 50-85、环境 24-35
  "depth_of_field": "shallow",  // shallow / moderate / deep
  "light_key": "soft warm key from camera left, gentle cool fill, subtle rim on hair",
  "light_quality": "diffused overcast",   // diffused / hard / atmospheric
  "composition": "center-framed, slight headroom, negative space on right"
}
```

配套改动：
1. **prompts.py `_board_rules` 第 6 条扩写**：prompt_en 每镜必须包含"光线方向+质量"句（示例给出 2-3 个模板短语）；camera_recipe 槽位必填且与 prompt_en 描述一致。
2. **禁画风词规则改为"禁抽象词、允许摄影事实词"**：`_clean_prompt_camera` 现有清洗不动；新增禁词表只留抽象词（cinematic/film still/8k/masterpiece），放行 bible 中已有的具体词（grain/halation/teal-and-amber 等，因为 VisualBible 是全片唯一画风来源，分镜不写画风、但可写摄影事实）。
3. **构图指令**：规则第 6 条加"构图槽位可选写 headroom/三分法/居中，写则必须可辨识"。

### P1：角色/场景锚点 verbatim 复用——提升跨镜一致性

1. **分镜规则第 6 条改**：角色指代必须从该角色 `identity_anchor` 中选取**固定短语切片逐字复用**（如"两条紧实麻花辫系浅蓝缎带"），禁止自由改写外貌。LLM 输出后由确定性校验抽查：分镜 prompt 中角色外貌词与该角色 anchor 的命中率（如 ≥1 个 anchor 短语命中/角色/镜）。
2. **story_assets 角色加 `pose_library` / `expression_library`**：每角色 3-5 个命名姿态/表情（英文短语），分镜 LLM 的 pose/expression 从库里取 id 或短语，保证跨镜表演一致。
3. **场景 plate 合并光照**：`plate_prompt` 生成时注入首 lighting 状态的方向/色温短语；可选新增"推荐机位"提示（地洞→24mm 低机位等，属摄影事实）。

### P2：质量门（确定性校验，参照 drama 门机制）

新增 `check_prompt_quality.py`（或并入 gate）：
1. **segments 段级**（P0 配套）：段 text 与整镜 prompt 词集重合率 ≤30%；同镜段间相似度 ≤40%；段含动作动词率 100%；段非空 ≥8 词。
2. camera_recipe 槽位非空率（目标 100% 必填，除 insert/pov 允许缺 composition）。
3. 光线词命中率：每镜 prompt 含 light 方向词（left/right/from/behind/overhead/key/fill/rim/warm/cool）≥1。
4. 角色锚点复用率：每镜引用的角色 ≥1 个 anchor 短语命中。
5. 抽象画风词残留率：0（cinematic/film still/8k/masterpiece/ultra-detailed 等）。
6. 每镜动作数 ≤1（与 audit_storyboard 现有"一段一动作"合并统计）。

产出：report 级（warn/block 阈值可配，先 warn 后收紧）。

### P3：素材注入链核对（ComfyUI 侧）

- 核对 `ComfyUI对接指南.md`：story_assets 的角色图/场景图/道具图是否真的作为 ref_image 注入对应镜头（Seedance 官方：角色 1-2 图 + 场景 1 图 + 运镜 1 + 音频 1，**不堆满**）。若资产图未注入，提示词再细也救不回一致性——这是"质量低"的第二大嫌疑点。
