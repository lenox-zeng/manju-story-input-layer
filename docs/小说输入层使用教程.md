# 小说输入层使用教程（`python -m manju.story_cli`）

目标：**只需要提供一部小说/短故事**，自动完成解析、压缩、分集，产出 v10.2 渲染契约（plan / script / storyboard / director）与故事层报告，再交给下游渲染流水线出图出片。

> **两种入口，同一套流水线**：本教程讲命令行 `python -m manju.story_cli`；图形界面见
> `docs/Studio使用教程.md`。Studio 的「生成」页在后台调用同一个 `story_cli`，
> 「发布契约」复用同一套编译与 gate/drama 审计，两种方式产出的契约完全一致。

```
小说.txt
  → ⓘ 解析：编码识别 → 预处理清理（广告/网址/格式）→ 章节表（无章节按 2 万字切段）
  → ⓘ 压缩：5 章/卷 → 卷事件摘要 → 全书法典（≤30k 字短篇跳过）
  → ⓘ 情节分集：有序情节原子 → LLM 按戏剧单元决定集数/每集 must_show → ep_src_NNN.txt
  → ① 全局圣经（角色/场景/道具/爽点，含 series_design）
  → ② 分集梗概（每批 ≤3 集，写入 must_show/key_props/因果链）
  → ③ 角色身份锁 cast
  → ④ 场景/道具美术 art
  → ⑤ 剧本（本集切片 + 前后集梗概）
  → ⑥ 2D 站位（本集切片 + 前后集梗概）
  → ⑦ 分镜（逐场顺序生成，携带 state_in / state_out）
  → ⑧ 确定性编译 v10.2
  → input/<小说名>/external/plan.json + input/<小说名>/external/epNN/{script,director}.json + input/<小说名>/epNN/storyboard.json
  → state/report/index.html + epNN.html + report.webp
  → 下游渲染流水线（完整联调包，不在本包内）
```

故事层与渲染层解耦：

- 故事层只输出 `manju/story/models.py` 里的结构化字段；
- 编译层 `manju/story/compile.py` 负责映射到 v10.2，**不调用模型**；
- 字段规范与校验规则见 `docs/漫剧文本输入契约_v10.2.md`。渲染适配器、能力注册表与工作流属**完整联调包**，不在本输入层包内；工作流升级不改变故事层与 LLM 提示词。

---

## 1. 前置条件

1. Python 3.11+，虚拟环境可用：`.venv\Scripts\python.exe`。
2. 文本模型 API 已配置：`config.json` 的 `llm` 段填好 `base_url / model`（**DeepSeek**，OpenAI 兼容），API Key 通过环境变量提供：
   ```powershell
   $env:DEEPSEEK_API_KEY = "<你的 Key>"
   ```
   也支持 `MANJU_LLM_API_KEY` / `OPENAI_API_KEY`；`--llm-url` 可临时覆盖端点。
3. 不需要本地 GPU、ComfyUI 或显存管理：本包只把小说编译成契约，出图/出片由下游渲染流水线负责。

> 不建议把 Key 明文写进 `config.json`。旧配置里的 `llm.api_key` 仍兼容，但 `--doctor` 会提示迁移；如果 Key 曾出现在终端/日志/聊天里，请先吊销再换新。

## 2. 输入解析（不调用模型）

`manju/story/ingest.py` 负责编码与章节识别，`--dry-run` 只解析、不调用 LLM、不写盘。

### 2.1 编码自动识别

按顺序尝试：UTF-8、UTF-8 BOM、UTF-16（含无 BOM 的启发式判断）、GBK / GB18030。二进制文件或空文件会明确报错。

### 2.2 章节识别

识别行首标题，最长 60 字符：

- `第X章 / 回 / 节 / 卷 / 部 / 篇 / 集`（中文数字、阿拉伯数字、全角数字）；
- `楔子`、`序章`、`序言`、`序幕`、`引子`、`前言`；
- `尾声`、`终章`、`后记`；
- `番外`、`番外篇`、`番外 3`；
- `Chapter N`、`Part N`、`Volume N`（罗马数字或阿拉伯数字，大小写不敏感）。

章节表包含：序号、标题、起止偏移、类型、字数。正文前的非标题内容归入“前言”段。

### 2.3 预处理清理（默认开启）

定位：**小说拿到手后的第一道工序**，在章节识别与分集之前执行；纯规则、不调用 LLM，幂等（重复执行结果一致）。

会做：

- 统一换行（CRLF/CR → LF），去掉 BOM、零宽字符与控制字符；
- 去掉网页抓取带进来的 `<script>/<style>`、常见 HTML 标签与实体；
- 压缩连续空格/制表符；去掉中文标点两侧和**两个汉字之间**的排版空格；**标题行除外**，所以“第一章 开始”不会被改成“第一章开始”；
- 删除整行明显的网址/站点/广告（限短行）：`www.xxx.com`、`http://...`、“请收藏本站”“无弹窗”“最新章节”“请记住本站”“求月票”等；
- 删除 `*** / --- / …… / ~~~~` 等分隔线（替换为空行）；
- 正文行内夹带的网址只摘掉网址，保留其余文字。

不会做：

- 不改写正文措辞，不自动修复乱码（乱码只报告，人工改字风险更高）；
- 不删除章节标题、作者名、书名、“作者的话”等内容；
- 不覆盖原文件。

结果与复核：

- `--list-chapters` / `--dry-run` 会打印清理后的当前字符、有效字符、汉字数，以及“原始 → 当前”字符数与删除了多少行、按类别统计；
- 内容有变化时，工作目录写 `cleaned.txt` 与 `cleanup_report.json`（含删除样例与被删比例）；
- 删除的有效字符超过 10% 会告警，提示检查是否误删；
- 关闭清理：`--no-cleanup`。

> 字数口径：`原始字符` 是文件字符数（含空格/换行）；`有效字符` 去掉所有空白；`汉字` 只统计纯汉字。分集与时长估算优先看“有效字符/汉字”，不要用文件大小。

### 2.4 无章节回退

整本没有识别到章节时：

- 按 `llm.story_fallback_chunk`（默认 20000 字）切段；
- 相邻段重叠 `llm.story_fallback_overlap`（默认 500 字）；
- 尽量在换行/句末处收尾，避免把一句话劈开；
- 章节模式下找不到章节时，会自动回退为按字数分集并打印告警。

### 2.5 查看章节表

```powershell
# 只看编码、总字数、章节表
python -m manju.story_cli input\my_story.txt --list-chapters

# 解析 + 自动分集预演，不调用 LLM、不写盘
python -m manju.story_cli input\my_story.txt --dry-run --yes
```

也可以单独运行解析器：

```powershell
python -m manju.story.ingest input\my_story.txt --list-chapters
python -m manju.story.ingest input\my_story.txt --json
```

## 3. 自动分集

### 3.1 默认规则：按故事情节分集

`--episodes auto`（默认）+ 未指定人工分集/章节数 + `llm.story_plot_mode=true` 时，
走**情节模式**：

1. 把清理后的全文按约 2400 字切成有序“情节原子”（保持原文偏移，不重不漏）；
2. LLM 通读原子摘录，按“目标 → 阻力 → 转折 → 代价/高潮 → 新问题”划分戏剧单元，
   自行决定集数，并为每集写 2–6 条（通常 4–6 条）`must_show`（必须让观众看见的具体事件）、
   0–3 件 `key_props`、`dramatic_question / turn / climax / hook / cliff`；
3. 代码确定性修复原子区间：跳段/重叠/漏尾会被补齐，保证全文恰好覆盖一次；
4. 每集切片写 `ep_src_NNN.txt`，后续剧本/分镜逐条对账 `must_show`。

> 关键点：**原子区间是素材范围，不等于都要拍**。90 秒只演透 4–6 条（最少 2 条）must_show，
> 其余原文事件作背景/留白；不再硬把 9000 字或 2 章塞进一集。

长篇只做前 N 集时用 `--from-episode 1 --to-episode N`。设计阶段只读前
`N × llm.story_plot_prefix_chars_per_episode` 字（默认 5000/集），并自动把截断点
对齐到最近的句末/换行（前后 200–400 字内）；设计完成后只保留前 N 个戏剧单元：
既不为还没生成的后文付 token，也避免前几集被整本书稀释。
例如 90 万字小说只做前 2 集，默认只把前 1 万字交给分集设计，而不是把全书塞进上下文。

```powershell
# 预览情节原子（不调 LLM）
python -m manju.story_cli input\my_story.txt --dry-run --yes
# 正式生成
python -m manju.story_cli input\my_story.txt
```

显式 `--episodes N`、`--episode-map`、`--chapters-per-episode` 会关闭情节模式，
回到下面的章节/字数分集；也可用 `--no-plot-mode` 强制关闭。

### 3.2 章节/字数分集（显式关闭情节模式）

在章节/字数模式下（情节模式已显式关闭），`--episodes auto` 时优先按**作者章节**分集：

```text
每 N 章 = 1 集
N = --chapters-per-episode，否则取 llm.story_chapters_per_episode（默认 0=关闭）
```

情节模式是默认值；只有显式给出 `--chapters-per-episode N`（N>0）才走章节分集。
章节能表达作者的叙事节奏（起承转合、钩子位置），比按字数硬切更贴近“一集一个完整段落”。示例：

```powershell
python -m manju.story_cli input\my_story.txt --chapters-per-episode 2
python -m manju.story_cli input\my_story.txt --chapters-per-episode 3
```

字数只作为**安全阀**，避免章节本身过长/过短：

1. 一组章节超过 `1.5 × llm.story_chars_per_episode`（默认 13,500 字）时，按段落拆成多集；
2. 一组章节少于 `max(1000, llm.story_chars_per_episode / 3)`（默认 3,000 字）时，向前并入相邻集，避免“200 字一集”；
3. 每次分组仍保证首尾相接、不重叠、不漏字；
4. `--episodes N` 与 `--chapters-per-episode` **互斥**：显式给总集数时按字数模式切（公式 `ceil(总字数 / story_chars_per_episode)`，仍优先吸附章节边界）；
5. `--episode-map` 优先级最高，用于人工指定章节/偏移；
6. 没有识别到章节时，章节模式自动回退为按字数分集并告警；
7. 每集切片写到 `state/story/<小说名>/ep_src_NNN.txt`。

> 注意：`--episodes N` 是“把整部小说切成 N 集”，不是“只生成 N 集”。长篇小说只做前几集请用 `--from-episode 1 --to-episode 2`。

### 3.3 超过自动上限

`llm.story_max_auto_episodes` 默认 12。自动分集超过 12 集时：

- 交互终端会要求确认；
- 非交互环境（CI / 管道）必须显式加 `--yes`，否则退出码 2；
- 也可显式给集数或人工分集表绕过。

### 3.4 人工分集

`--episode-map` 接受两种 JSON 格式，集号必须连续且文本不允许重叠：

```json
{
  "1": {"chapters": [1, 12]},
  "2": {"chapters": [13, 30]},
  "3": {"start": 120000, "end": 240000}
}
```

或数组：

```json
[
  {"ep": 1, "chapters": [1, 12]},
  {"ep": 2, "start": 120000, "end": 240000}
]
```

```powershell
python -m manju.story_cli input\my_story.txt --episode-map my_episodes.json
```

### 3.5 范围生成 / 断点续跑

```powershell
# 只处理第 5–20 集
python -m manju.story_cli input\my_story.txt --from-episode 5 --to-episode 20

# 复用已通过质量门的中间产物
python -m manju.story_cli input\my_story.txt --resume
```

- 范围外集不生成、不编译；
- `--from-episode N`（N>1）会读取 `state/story/<小说名>/board_ep{N-1}.json`，把上一集 `state_out` 作为第 N 集 `state_in`；
- 剧本侧同样衔接：读取 `state/story/<小说名>/script_ep{N-1}.json` 作为上一集剧本末态，第 N 集写戏时可见上一集结尾（跨集承接不因范围跳跃而断）；
- 上一集缓存不存在时打印 WARN，并从空状态开始。

## 4. 长篇小说压缩

### 4.1 短篇

法典文本 ≤ `llm.story_source_chars`（默认 30000 字）时**不压缩**，直接进入全局圣经阶段。
压缩是有损的：短篇不压，才能保住因果链和关键道具。

### 4.2 分卷摘要

超过 30000 字时：

1. 按 `llm.story_volume_chapters`（默认 5 章）分卷；
2. 每卷生成事件摘要：谁做了什么、结果、道具、空间细节、`new_entities`；
3. 合并为连续全书法典，最终不超过 `llm.story_source_chars`（默认 30000 字）；
4. 卷数上限 `llm.story_max_volumes`（默认 60）；超过时只压缩前 60 卷，并**显式**标记 `truncated`、记录被省略的章节范围。

卷摘要逐卷缓存为 `state/story/<小说名>/volume_NNN.json`，`--resume` 时复用。

> 不会静默截断：`truncated` 标记与警告会同时出现在 CLI 输出和卷摘要/大纲的 warnings 中；没有单独的 `codex.json` 文件。

### 4.3 配置

```json
{
  "llm": {
    "story_source_chars": 30000,
    "story_chars_per_episode": 9000,
    "story_chapters_per_episode": 0,
    "story_plot_mode": true,
    "story_plot_atom_chars": 2400,
    "story_plot_atom_excerpt": 900,
    "story_plot_max_atoms": 180,
    "story_plot_total_chars": 100000,
    "story_plot_prefix_chars_per_episode": 5000,
    "story_plot_episode_batch": 3,
    "story_volume_chapters": 5,
    "story_max_volumes": 60,
    "story_fallback_chunk": 20000,
    "story_fallback_overlap": 500,
    "story_episode_batch": 10,
    "story_max_auto_episodes": 12,
    "story_gate_attempts": 3
  }
}
```

`story_gate_attempts` 是每个阶段没过质量门时的最大重写次数（默认 3）。

## 5. 两级大纲与按集取源

### 5.1 全局圣经 + 分集梗概

- **全局圣经**：改编决策、spine、power_rule、角色/场景/道具表、爽点；不含分集梗概；
- **分集梗概**：按批生成，每批最多 `llm.story_episode_batch`（默认 10）集；
- 每批缓存为 `state/story/<小说名>/episodes_batch_NNN.json`，`--resume` 只重跑未过门的批次。

### 5.2 只给本集需要的源文

剧本 / 站位 / 分镜不再使用 `source[:4000]`：

| 阶段 | 输入 |
|---|---|
| 剧本 | 本集切片（最多 6000 字）+ 前后集梗概 + 全局圣经 |
| 站位 | 本集剧本 + 本集场景美术 + 本集切片（最多 6000 字） |
| 分镜 | 本集剧本 + 本集场景/站位 + 本集切片（最多 5000 字） |

切片超长时保留头 60% / 尾 40%，中段显式标记省略，不伪装成完整原文。

## 6. 常用参数

```powershell
# 自动分集（默认）
python -m manju.story_cli input\my_story.txt --yes

# 显式集数、每集 120 秒、竖屏
python -m manju.story_cli input\my_story.txt --episodes 3 --duration 120 --ratio 9:16

# 调整每集字数预算
python -m manju.story_cli input\my_story.txt --chars-per-episode 7000 --yes

# 人工分集
python -m manju.story_cli input\my_story.txt --episode-map my_episodes.json

# 只解析/分集，不调 LLM、不写盘
python -m manju.story_cli input\my_story.txt --dry-run --yes

# 只看章节表
python -m manju.story_cli input\my_story.txt --list-chapters

# 先只出大纲（P0 阻塞点），审阅后才继续
python -m manju.story_cli input\my_story.txt --review-outline
# 修改 state/story/<小说名>/outline.json 后批准并继续
python -m manju.story_cli input\my_story.txt --approve outline --resume

# 先只出大纲/角色/美术，人工确认提示词
python -m manju.story_cli input\my_story.txt --review

# 确认后继续（复用已通过质量门的中间产物）
python -m manju.story_cli input\my_story.txt --review --resume

# 质量门失败时先写失败包，再交互等待修复后重试
python -m manju.story_cli input\my_story.txt --on-gate-fail ask

# 软门恢复为错误（默认只记 warning）
python -m manju.story_cli input\my_story.txt --strict

# 覆盖已有 input 产物
python -m manju.story_cli input\my_story.txt --force

# 只清除当前小说临时工作目录（.work_<小说名>）后从头生成；已成功的成品保留
python -m manju.story_cli input\my_story.txt --clean --yes

# 关闭报告（默认生成）
python -m manju.story_cli input\my_story.txt --no-report
```

> `--plates`、`--run anchors|full`、`--manage-vram`、`--review-assets`、
> `--approve assets` 属于**完整联调包**的渲染/出图链路，本包不提供。本包只输出
> `story_assets.json` 资产清单与契约。

## 7. 质量门分级

生成阶段每完成一步都会跑确定性校验；不过门会把错误原文回喂给模型重写。

### 7.1 硬门（始终报错）

**ID 与引用**
- 角色 / 场景 / 道具 ID 闭环，不能引用不存在的对象；
- 剧本、站位、分镜的场次与人物必须与上游一致。

**时长**
- 单镜默认 1–3.2 秒（`story.min_shot_seconds` / `story.max_shot_seconds` 可配）；
- 每场切镜合计 = 剧本场时长（±0.3 秒）；
- 全集合计 = 单集目标（±15%）。

**台词**
- 对白只允许画内；speaker 必须在本场人物里；
- 必要的前情/规则/时间跳跃与角色内心，写入结构化 `scene.narration`（`exposition` / `inner`），叠在动作拍上、不做口型；旁白不得复述可见动作；
- 第 2 场起必须能说清 `transition_in`（match_cut / sound_bridge / action_bridge / time_jump / fade / dissolve）；bridge 类必须有共享 anchor，避免无动机硬切；
- 单句 ≤18 个汉字（`story.max_line_chars` 可配，下游 drama 审计读取同一值）；
- 台词时长不得超过所在切镜。

> 旁白与转场由 `story.narration_mode` / `story.transition_mode` 控制（默认 `auto`）。
> `narration_mode="off"` 表示**不允许**写旁白（写了会 block）；`transition_mode="off"`
> 表示关闭“第 2 场起必须有转场”的强制（缺失降为 warning），但已写出的转场仍做结构校验。
> 完整的配置默认值见根目录 `README.md` 的“引擎能力”表。

**画面**
- 同一画幅内正脸角色数**默认不限**；配置 `story.max_faces_per_shot` 后才按该上限校验，超出时可用 `allow_multi_face` 显式说明全员背影/剪影；
- `prompt_en` 必须非空；角色定妆、场景美术、分镜首帧的提示词语言由 `story.prompt_language` 统一控制（默认 `en`，可设 `zh`/`any`），禁止镜头运动词与画风词；
- 每镜必须为每个启用画幅提供 `framing`（`shot_size` / `subjects` / 构图）；缺任一启用画幅会被硬门拦下；
- `subjects` 必须覆盖 `characters`。

**情节（情节模式）**
- 每条 `must_show` 必须落到至少一场（`major_event` 原样认领，或场次文本中真的演出）；
- 第 2 场起必须有 `causal_from`，且能看出承接上一场的结果；
- 每件 `key_prop` 必须真正出场，并有一个 `coverage=insert`、`emphasis=key_prop`、`visual_focus=道具名` 的特写拍；
- 每个 `emphasis` 拍必须有 `visual_focus`；`key_prop` 拍在分镜层强制 close/extreme-close + 非静态运镜。

**结构与钩子**
- 最后一场必须是“结尾钩子”；
- `hook_beat` 必须在前 3 拍内；
- 分镜节拍必须连续覆盖，不能漏拍。

### 7.2 软门（默认 warning，`--strict` 恢复为错误）

- 每集 5–8 场（90 秒；场次过多会变成每场一个跳切）；
- 6–12 句台词；对白稀疏自动模式下降到 2–6 句、≤160 字，并提高 reaction/insert coverage；
- 20 秒内有一次“抉择”；
- 15–60 秒内有“受挫/代价”且 `cost` 非空；
- 连续 3 集至少 1 个爽点。

### 7.3 编译后

- 编译器把分镜总时长规范化到单集目标：不破坏台词时长的前提下均摊差值，每镜保持在配置的时长区间内，保证下游 `scene_sum` / `episode_sum`（±0.2s）通过；
- 自动跑 `manju.gate` 与 `manju.drama` 的严格审计；有 block 就报错并返回非零退出码。

## 8. 连续性

每个 cut 必须声明 `state_out`：

```json
{
  "where":    {"C1": "north"},
  "facing":   {"C1": "south"},
  "posture":  {"C1": "standing"},
  "wardrobe": {"C1": "C1-default"},
  "props":    {"P1": "C1"},
  "injuries": {"C1": "left arm bandaged"}
}
```

`where` / `facing` 使用受控方向词表，其它字段为自由文本。

确定性检查：

- 同一场顺序生成：`state_in` = 上一场终态，`previous_cuts` = 最近两镜；
- 位置跳变、朝向/站位突变、服装回退、道具转移或消失、伤势回退 → 报错；
- 相邻镜：越轴 / 180°、视线不接、景别跳变；
- 整集分镜完成后审计；跨集 `state_out` → 下一集 `state_in`；
- 范围生成时从上一集缓存继承终态（见 3.4）。

### 8.1 分镜提示词与角色身份（输入层边界）

输入层不决定实现层用哪种人物一致性技术。分镜 `prompt_en` 固定只写动作瞬间、
姿态、表情、视线、位置、场景与光线；**不写**姓名、脸部、身材、发型、固定服装
或站姿。这样提示词不会把定妆照的姿势和背景带进每一镜，也不会浪费 token。

角色身份以结构化数据输出：

- 分镜里的 `ref_characters`、`subjects[].expression`、`wardrobe_state`；
- `input/<小说>/story_assets.json` 里的完整 `identity_prompt` 与短
  `identity_anchor`。

实现层按自己的技术选择怎么用：

| 实现层技术 | 做法 |
|---|---|
| IPAdapter / PuLID / InstantID / 角色 LoRA / 人脸替换 | 用参考图、视角图与表情图；`prompt_en` 保持精简 |
| 纯文生视频（无参考图） | 自行把 `story_assets.json` 的 `identity_prompt` 拼进最终提示词 |
| 6 视角 + 7 表情等多参考图 | 按镜头语义选图（特写取表情、朝向取侧/背、俯仰取高低机位），提示词只写表演 |

输入层不再有 `story.prompt_identity_mode`；旧配置中的该键会被忽略。若提示词
策略升级，`--resume` 只会重建 `shots_*` / `board_*_scene*` 这类含逐镜提示词的
缓存，不会连带重跑圣经/大纲/剧本。

## 9. 角色资产清单（本包只输出清单，不生成图片）

本包不调用任何图像模型，也不生成 `identity.png`、三视图、表情或服装板。它把渲染层需要的资产需求写入 `input/<小说名>/story_assets.json`：

- **角色**：`identity_prompt`、`identity_anchor`、服装状态、表情与视角建议；
- **场景**：空镜 plate 提示词、空间锚点、光照；
- **道具**：提示词与尺度。

完整联调包/渲染层负责后续步骤：生成角色身份图与多视角/表情/服装资产、按镜头语义选择参考图、缺资产时中止而不是静默换脸，以及可选的 DINOv2/CLIP 人脸相似度 QA。

输入层的职责边界是：**清单字段完整、引用闭环、可审计**。具体用参考图、锁脸还是纯文本方案维持人物一致性，由实现层决定。

## 11. 人工干预流程

人工只卡高杠杆节点；确定性检查仍然自动执行。

### 11.1 大纲审批（P0，阻塞）

1. 生成大纲并停下：
   ```powershell
   python -m manju.story_cli input\my_story.txt --review-outline
   ```
2. 打开 `state/review/outline.html`（或 `outline.md`）审阅改编决策、故事脊柱、角色、场景、道具、爽点与分集梗概。
3. 直接编辑 `state/story/<小说名>/outline.json`。
4. 批准并继续：
   ```powershell
   python -m manju.story_cli input\my_story.txt --approve outline --resume
   ```

审批记录的是大纲内容哈希。批准后再改 `outline.json`，哈希失效，必须重新 `--review-outline` 审阅，不能直接空批准。

### 11.2 角色身份图审批（P1，完整联调包）

身份图审批需要渲染侧先产出 `assets/characters/<Cid>/identity.png`，属于**完整联调包**。本包只输出 `story_assets.json` 资产清单，不生成也不审批图片，因此没有 `--review-assets` / `--approve assets` 参数。

### 11.3 质量门失败升级（P1）

硬门/软门仍自动判定。失败时写失败包：

```
state/review/failures/latest.md
state/review/failures/<时间戳>.md
state/review/failures/<时间戳>.json
```

默认 `--on-gate-fail stop` 退出；加 `--on-gate-fail ask` 会在终端等待修复，输入 `r` 用 `--resume` 重试，输入 `q` 退出。非交互环境不会挂起，直接退出。

### 11.4 角色/美术审查（原有流程）

1. 第一次用 `--review`，只生成 `outline.json / cast.json / art.json`。
2. 检查：
   - 角色 `identity_lock` 是否一眼能区分（身高、发型、脸型、服装色）；
   - `wardrobe_states` 是否覆盖剧情变化（受伤、湿身、换装）；
   - 场景 `image.prompt` 是否为空景、语言符合 `story.prompt_language`、无角色名；
   - 道具是否有 3–5 个可复用锚点。
3. 直接编辑 `state/story/<小说名>/*.json`，然后：
   ```powershell
   python -m manju.story_cli input\my_story.txt --review --resume
   ```
4. 某一步连续重写仍不过门时，先看失败包；修中间文件后 `--resume` 只重跑失败的下游阶段。

> `--resume` 只复用**通过质量门**的缓存；缓存不过门会自动重生成。人工修改的 `outline.json` 会优先于旧缓存。

### 11.5 审批文件

| 文件 | 作用 |
|---|---|
| `state/review/approvals.json` | 大纲批准账本（含内容哈希、时间、目录） |
| `state/review/outline_required.json` | 大纲待审阅标记 |
| `state/review/outline.html` / `outline.md` | 大纲审阅页 |
| `state/review/failures/latest.md` | 最近一次质量门失败包 |

> 身份图审阅页（`assets.html` / `assets.md`）由完整联调包在出图后生成，本包不产出。

`--ignore-review` 可显式跳过未批准的大纲阻塞，仅用于脚本化调试，不建议用于正式生产。

## 13. 能力与工作流解耦

本输入层包**只产出契约**，不包含任何渲染实现（ComfyUI 客户端、能力注册表、适配器、工作流 JSON）。

字段定义见 `docs/漫剧文本输入契约_v10.2.md`；**下游实现层怎么读、字幕/TTS/口型/旁白/转场怎么接，见 [`docs/ComfyUI对接指南.md`](ComfyUI对接指南.md)**。渲染适配器、能力清单与工作流属于**完整联调包**，不在本包内。替换模型或工作流时只改联调包一侧，故事层模型、校验器、LLM 提示词不需要改。

**交接时只给三样**：契约、目标平台的对接指南、一份完整样例（如 `input/<小说名>/`；纯净包不含生成结果，样例需单独提供）。契约是唯一标准；平台指南只做读取与映射，不复制契约，也不交付 `manju/schemas.py` / `gate.py` / `drama.py`。

## 14. 常见问题

| 现象 | 处理 |
|---|---|
| `文本模型服务不可用` | 检查 `config.json` 的 `llm` 段（base_url/model），或用 `--llm-url` 指定；确认环境变量 `DEEPSEEK_API_KEY` 已设置，`--doctor` 可看 Key 来源 |
| `plan.json 已存在` | 加 `--force`，或改 `--out` |
| 自动分集超过 12 集被拒 | 加 `--yes`，或显式给 `--episodes N` / `--episode-map` |
| 章节识别不全 | 用 `--list-chapters` 看章节表；标题必须独占一行且 ≤60 字符 |
| 预处理疑似误删正文 | 看 `cleanup_report.json` 的 `examples`/`removed_ratio`；确认后重跑时加 `--no-cleanup` |
| 章节分集得到太多/太少集 | 用 `--chapters-per-episode` 调每集章数；或显式 `--episodes N` 走字数模式 |
| 某章太长被拆成多集 | 正常安全阀行为：单组超过 1.5×`story_chars_per_episode` 会按段落拆 |
| 某阶段连续重写不过门 | 看 `state/story/` 下对应 JSON 与门报告；改文件后 `--resume` |
| 生成的分镜人物同框过多 | 默认不限制人脸数；若你的引擎只能锁一张脸，在 `config.json` 设 `story.max_faces_per_shot: 1`，优先单人反打/过肩/背影 |
| 角色图片生成/缺图报错 | 属于下游渲染层；本包只输出 `story_assets.json` 清单，不生成图片 |
| 报告没有截图 | 安装 Chrome/Edge，或忽略占位图；HTML 仍可正常打开 |
| 成片没有旁白/心声 | 下游需读取 `shot.narration`，不要只读 `shot.audio`；见 `docs/ComfyUI对接指南.md` |
| 场与场之间仍是硬切 | 下游需读取场次首镜的 `transition_in`；bridge 类不需要视觉特效，但需要按 anchor 做声音/动作承接 |
